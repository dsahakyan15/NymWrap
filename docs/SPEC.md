# NymWrap — спецификация для ИИ-агентов

Этот документ описывает, **что** строим и **как устроена система**. Правила работы
с репозиторием лежат в [`AGENTS.md`](../AGENTS.md), модель угроз и требования
безопасности лежат в [`THREAT_MODEL.md`](THREAT_MODEL.md).

---

## 1. Задача

### 1.1 Постановка учителя

> Sargum em cragir, vor@ arden isk dzer masin goyutyun unecox u havaqagrvac
> tvyalner@ dem piti payqari, voncvor pahvacqain amenorya, nenc el AI um dzer
> arden isk arac requestneri. Vorpisi kamac kamac dzer masin yndhanur karciq@
> hamakargi mot poxvi, te inchov eq zbaxvum, inch eq sirum, yerb vonc.

Перевод: нужна программа, которая борется с данными о человеке, уже собранными и
собираемыми каждый день, в том числе с тем, что ИИ-сервисы знают по его прошлым
запросам. Цель: чтобы **постепенно** менялось общее представление системы о
человеке — чем он занимается, что любит, когда и как он активен.

### 1.2 Источники, из которых собрано решение

| Источник | Что взяли |
|---|---|
| Урок `web3lesson/` (anti-persona) | Локальное исследование следов (история браузера, чаты с ИИ), построение персоны, план **постепенного дрейфа** через «мостовые» этапы, проверка плана эмбеддингами, исполнение в браузере в человеческом темпе, метрики дрейфа. Плюс `ROADMAP.md`: расширение вместо Playwright, импорт Takeout и официальных экспортов, снимки ленты, режим «делаешь сам», фильтр вредных целей, шифрование персоны |
| Пост Виталика Бутерина (16.10.2026), «paranoid mode» | Локальный OpenAI-совместимый демон: **отдельная Tor-цепочка на каждый разговор**, **cover-трафик**, **локальное переписывание промптов** своей моделью, **zkAPI** (оплата ETH без связи запросов с плательщиком), агент в песочнице **bwrap** (или MicroVM) и под `torsocks`. Его же оговорка: Tor не оптимален, cover-трафик слаб против сговора провайдера с guard-узлом; лучше специализированный **mixnet** с постоянным cover-трафиком |
| Ветка `vbuterin/zkapi` `feat/client-concession-local` | Идеи клиента `zkapi-clientd`: изоляция разговоров в Tor, каноническое переписывание промптов, **отдельная история на стороне провайдера**, ограниченный по бюджету cover-трафик. Ветка помечена как не готовая к продакшену |

### 1.3 Главная идея решения: две полосы

Урок и пост решают две половины одной задачи:

- урок **меняет** уже накопленный профиль (добавляет новый сигнал);
- пост **перекрывает** утечку новых данных (реальный сигнал перестаёт попадать в профиль).

Один только шум не работает: если к живому аккаунту добавить шум, а реальная
активность продолжает идти туда же, модели профилирования отделяют шум от сигнала
(классическая слабость TrackMeNot). Поэтому NymWrap делит всю активность человека
на две **полосы** (lane), которые никогда не смешиваются:

| | **Теневая полоса** (shadow lane) | **Полоса легенды** (cover lane) |
|---|---|---|
| Кто ты для сервиса | никто: без логина, без cookies, своя цепочка Tor на каждый разговор | твой настоящий аккаунт (Google, YouTube, ChatGPT…) |
| Что туда идёт | твои **реальные** вопросы и поиски, обезличенные и переписанные | только **легенда**: постепенный дрейф к выбранному образу |
| Цель | новые реальные данные о тебе перестают копиться | профиль аккаунта плавно смещается к легенде |

Итог для аккаунта: `профиль = (старая история − самые сильные сигналы) + дрейф`,
а реальный сигнал уходит в анонимную полосу. Отсюда четыре модуля:

1. **Shield** — теневая полоса: анонимный шлюз для ИИ и поиска (идеи Виталика).
2. **Drift** — полоса легенды: постепенный дрейф профиля (идеи урока).
3. **Purge** — уменьшение старого: выборочное удаление самых характерных следов,
   стирание памяти ИИ, запросы на удаление данных.
4. **Mirror** — измерение: что сервисы «думают» о человеке сейчас и как это меняется.

## 2. Глоссарий

Эти слова используются в коде, документах и промптах одинаково.

| Термин | Значение |
|---|---|
| **lane / полоса** | `shadow` или `cover`. Каждый запрос, процесс и файл данных принадлежит ровно одной полосе |
| **persona / персона** | модель того, кем человек выглядит по своим данным (из урока) |
| **cover / легенда** | целевой образ, к которому дрейфует профиль аккаунта; выбирает пользователь |
| **stage / этап** | шаг плана дрейфа; соседние этапы делят общий «мост» (bridge) |
| **conversation / разговор** | единица изоляции в Shield: своя цепочка, свой одноразовый удостоверяющий токен, своя история на стороне провайдера |
| **circuit / цепочка** | Tor-цепочка или маршрут mixnet, привязанный к одному разговору |
| **vault / хранилище** | зашифрованная таблица соответствий `плейсхолдер ↔ реальное значение` |
| **canary / канарейка** | тестовая секретная строка; её появление в исходящем трафике — провал |
| **egress / выход** | любой байт, уходящий с машины. Выход разрешён только процессу `nw-netd` |
| **leakcheck** | детерминированная проверка исходящего текста на наличие значений из vault и PII |
| **trust level** | уровень анонимности маршрута, L0–L4 (см. §4.7) |
| **profile** | набор настроек `standard` / `strict` / `paranoid` (см. §8) |
| **fail-closed** | при любой ошибке транспорта запрос не уходит, прямого обходного пути нет |
| **hard data / жёсткие данные** | признаки устройства и окружения: IP, Wi-Fi/MAC, GPS, часовой пояс, локаль, имена ПК и пользователя, пути, идентификаторы железа, отпечатки протоколов, метаданные файлов (§4.9) |
| **секреты устройства** | жёсткие идентификаторы этой машины, собранные `nw-probe` и хранящиеся в vault как секреты |

## 3. Архитектура

### 3.1 Процессы и разделение привилегий

Система — набор маленьких процессов, как в OpenSSH: у каждого ровно те права,
которые нужны его работе. Компрометация одного процесса не даёт доступа к данным
другого.

```
                 ┌──────────────────────────── машина пользователя ────────────────────────────┐
  приложения,    │                                                                              │
  IDE, агенты ──►│  nw-api ──► nymwrapd (core) ──► nw-llmd (локальная модель, без сети)         │
  (OpenAI API)   │  unix socket    │  политика, конвейер Shield, vault, планировщик             │
                 │                 │                                                            │
  Tauri UI ─────►│                 ├──► nw-netd ──► Tor (arti) / Nym mixnet ──► ИИ-провайдеры,  │──► интернет
                 │                 │     единственный процесс с сетью; видит только              │
                 │                 │     уже переписанный текст                                  │
                 │                 │                                                            │
  расширение ───►│  nw-drift-host ◄┘  (полоса легенды: получает только план легенды)             │
  браузера       │  native messaging                                                            │
                 │                                                                              │
                 │  nw-audit (импорт Takeout, истории, экспортов ИИ; без сети, только чтение)    │
                 └──────────────────────────────────────────────────────────────────────────────┘
```

| Процесс | Полоса | Сеть | Файлы | Видит реальные данные |
|---|---|---|---|---|
| `nymwrapd` (core) | обе | нет | свой зашифрованный store | да, в памяти |
| `nw-api` | shadow | только локальный сокет | нет | да (входящий промпт) |
| `nw-llmd` | shadow | нет | модели только на чтение | да (после замены PII) |
| `nw-netd` | shadow | **да**, только через транспорт | только своё состояние Tor/Nym | **нет**, только переписанный текст |
| `nw-drift-host` | cover | нет (сеть делает браузер) | нет | **нет**, только план легенды |
| `nw-audit` | — | нет | исходные файлы только на чтение | да, на время импорта |
| `nw-probe` | shadow | нет | только чтение системных идентификаторов (§4.9.3), одноразовый | только секреты устройства |
| UI (Tauri) | обе | нет | нет | показывает пользователю |

Связь между процессами: unix domain sockets (Linux/macOS) или named pipes с ACL
текущего пользователя (Windows). Сообщения — типизированные структуры (serde,
версия схемы в каждом сообщении), каждая сторона проверяет схему и отвергает
лишние поля. Открытых TCP-портов нет, кроме опционального OpenAI-совместимого
`127.0.0.1` для программ, не умеющих в unix socket (см. §5.1).

### 3.2 Стек

Решение принято, менять через ADR (`docs/adr/`).

| Часть | Технология | Почему |
|---|---|---|
| Ядро и все демоны | **Rust** (tokio, axum, serde) | память без UB; arti и nym-sdk написаны на Rust и встраиваются как библиотеки |
| Tor | **arti-client** (встроенный) | изоляция потоков на уровне API, без внешнего `tor` |
| Mixnet | **nym-sdk** (опционально) | постоянный cover-трафик на уровне сети — то, что Виталик называет лучшей заменой Tor |
| Локальная модель | **llama.cpp server** или **Ollama** в песочнице, доступ через unix socket | своя модель, ничего не уходит наружу |
| Хранение | SQLite + **SQLCipher**, ключи XChaCha20-Poly1305 | шифрование «в покое», см. THREAT_MODEL §4 |
| Секреты в памяти | `secrecy`, `zeroize`, `mlock` | ключи и vault не остаются в памяти и swap |
| Песочницы | Linux: **bubblewrap + seccomp + network namespaces**, опц. Firecracker/cloud-hypervisor; Windows: AppContainer или WSL2; macOS: App Sandbox | изоляция по образцу Виталика |
| UI | **Tauri** | десктоп без локального HTTP-порта |
| Расширение | TypeScript, Manifest V3, Chrome и Firefox | работает в настоящем браузере пользователя (рекомендация ROADMAP урока) |
| Эмбеддинги | `nomic-embed-text` через ту же локальную модель | математика оси дрейфа из урока |

## 4. Модуль Shield (теневая полоса)

Задача: любой реальный запрос человека к ИИ или поиску уходит так, что провайдер
не может связать его с человеком, с другими его разговорами и с его аккаунтом.

### 4.1 Конвейер

Каждый исходящий запрос проходит этапы строго по порядку. Этап реализован как
отдельная функция `fn(Request) -> Result<Request, Block>` с собственными тестами.

| # | Этап | Что делает | Где выполняется |
|---|---|---|---|
| 1 | **classify** | определяет чувствительность: `local_only` (здоровье, финансы, документы, точные адреса, всё из списка пользователя) или `remote_ok`. `local_only` уходит только в локальную модель (L0) | core + nw-llmd |
| 2 | **minimize** | детерминированный поиск PII и жёстких данных (регулярки + словари + локальная NER, детекторы §4.9.3), **личного списка секретов** пользователя (имя, город, работа, имена близких) и **секретов устройства**. Каждое значение заменяется плейсхолдером `⟨PERSON_1⟩`, `⟨CITY_1⟩`; соответствие пишется в vault этого разговора | core |
| 3 | **canonicalize** | локальная модель переписывает текст нейтральным стилем: убирает лишний контекст, личные обороты, опечатки, характерную пунктуацию. Опционально **переводит на английский** (язык сам по себе выдаёт страну) | nw-llmd |
| 4 | **linkcheck** | сравнивает накопленную видимую провайдеру историю с досье пользователя и ≥50 синтетическими досье: закреплённые embeddings, детерминированное ранжирование, top-k и порог профиля; риск → локальное generalize нового хода и повторная проверка | core + embedding worker |
| 5 | **split** (при оставшемся риске) | разбивает задачу на независимые подвопросы с разными удостоверениями, цепочками и историей; каждый проходит linkcheck; невозможность безопасного разделения → L0 с объяснением | core + nw-llmd |
| 6 | **leakcheck** | детерминированно: после всех переписываний нет значений vault (точное и нечёткое совпадение, транслитерация), PII-шаблонов и канареек. Провал = `Block`, запрос не уходит | core |
| 7 | **shape** | приводит запрос к канонической форме: allowlist полей тела, длина дополняется до корзины, параметры модели нормализованы; заголовки и TLS строит `nw-netd` (§4.9.2) | core |
| 8 | **route** | выбирает провайдера, удостоверение и цепочку согласно trust level и профилю | core |
| 9 | **send** | передаёт запрос в `nw-netd` через очередь планировщика cover-трафика | nw-cover → nw-netd |
| 10 | **rehydrate** | в ответе плейсхолдеры заменяются обратно на реальные значения, при переводе ответ переводится обратно локально | core + nw-llmd |
| 11 | **present** | пользователь видит ответ; в `strict` и `paranoid` до отправки видит дифф «твой текст → что уйдёт» и подтверждает | UI |

Правила конвейера:

- leakcheck стоит **после** всех этапов с моделью: модель недетерминирована и может
  вернуть удалённое значение, поэтому последнее слово всегда за детерминированным кодом.
- Локальная модель на этапе 3 никогда не видит сырые значения из vault: они уже
  заменены на этапе 2.
- Ответ провайдера — недоверенные данные. Он не исполняется и не передаётся в
  инструменты агента без явного разрешения пользователя (см. THREAT_MODEL §6).

#### 4.1.1 Приёмка linkcheck

Досье (ADR 0053) включает подтверждённую персону, все личные и Device-секреты
и сводку импорта. Переписывание локальной копии не стирает уже отправленные
факты из оценки. Новая вкладка или ID с тем же L3-ключом не доказывают независимость.
Приёмка — ≥300 синтетических случаев EN/RU/HY с отдельным held-out, не
использованным при настройке: top-1 атакующего не выше 1/N с интервалом 95%,
канареек 0 и честный отчёт о полезных ответах, L0 и отказах. Все-L0 не заменяет
оценку реально отправленных запросов. Непроведённая оценка оставляет этап открытым.

### 4.2 Изоляция разговоров

- Новый разговор = новая цепочка (arti isolation token), новое одноразовое
  удостоверение (§4.6), новая пустая история на стороне провайдера.
- **История на стороне провайдера отдельна.** Локально хранится настоящая история
  (зашифрованная), провайдеру уходит только переписанная. Продолжение разговора
  отправляет переписанную историю этого же разговора, никогда — куски других.
- Длинный разговор провайдер может связать внутри себя, это неизбежно. Поэтому
  после `max_turns_per_conversation` (по профилю) Shield предлагает начать новый
  разговор с переписанным кратким содержанием.
- Между разговорами — случайная пауза перед первым запросом, чтобы время создания
  цепочки не совпадало с действиями пользователя.

### 4.3 Cover-трафик

Цель: провайдер и наблюдатель сети не могут отличить реальные запросы от приманок
и не могут восстановить ритм активности человека.

- **Приманки** генерирует локальная модель из пула синтетических персон (не из
  легенды пользователя и не из его данных). Приманки проходят тот же конвейер
  shape/route/send и неотличимы по форме.
- **Режим Пуассона** (`standard`, `strict`): приманки с заданной средней частотой.
- **Режим постоянной скорости** (`paranoid`): запросы уходят в слотах каждые
  `T ± jitter` секунд; если реального запроса нет, уходит приманка. Реальный
  запрос ждёт ближайшего слота — это цена анонимности (задержка).
- **Бюджет** ограничен: `max_cover_requests_per_day`, `max_cover_spend_per_day`.
  При исчерпании бюджета реальные запросы в `paranoid` ставятся в очередь, а не
  уходят «голыми».
- Ограничение, которое честно показываем пользователю: против провайдера в сговоре
  с guard-узлом Tor и активной манипуляции временем cover-трафик слаб. Для этого
  есть транспорт mixnet (§4.5).

### 4.4 Поиск в теневой полосе

- Поисковые запросы идут через `nw-netd` к поисковикам, работающим через Tor
  (onion-адреса, если есть), без cookies, с тем же конвейером minimize/leakcheck.
- Настоящий веб-сёрфинг NymWrap не заменяет: UI рекомендует Tor Browser или
  Mullvad Browser для реальной активности и считает долю активности, ушедшей в
  тень (метрика `shadow_share`, §7.3).

### 4.5 Транспорты (`nw-netd`)

| Транспорт | Когда | Свойства |
|---|---|---|
| `tor` (arti) | по умолчанию для remote | изоляция по разговору, DNS только через Tor |
| `nym` (mixnet) | `paranoid` или по выбору | Sphinx-пакеты, смешивание с задержками, постоянный cover-трафик на уровне сети |
| `local` | L0 | только `nw-llmd`, сети нет |
| `direct` | **отключён в сборке по умолчанию**, только флаг компиляции для отладки | — |

`nw-netd` работает в своём network namespace, где единственный маршрут наружу —
транспорт. Ошибка транспорта = ошибка запроса (fail-closed). Процессы, кроме
`nw-netd`, запускаются с `--unshare-net` и физически не могут открыть сокет наружу.

### 4.6 Удостоверения и оплата (`nw-cred`)

API-ключ связывает все запросы под ним с плательщиком. Поэтому:

| Механизм | Связываемость | Статус |
|---|---|---|
| **zkAPI** | запросы не связываются ни между собой, ни с депозитом: оплата ETH, проверка через доказательство с нулевым разглашением | адаптер к `zkapi-clientd`; ветка пока не для продакшена, поэтому модуль за флагом `experimental-zkapi` |
| **Пул предоплаченных ключей** | связываются запросы под одним ключом | ротация ключей по разговорам, честное предупреждение в UI |
| **Локальная модель** | ничего не уходит | всегда доступна, обязательна для `local_only` |

Адаптер реализует трейт `CredentialProvider { fn acquire(conv_id) -> Credential; fn release(...) }`,
поэтому новый механизм добавляется без изменения ядра.

### 4.7 Уровни доверия маршрута

| Уровень | Маршрут | Что может узнать провайдер |
|---|---|---|
| **L0** | только локальная модель | ничего |
| **L1** | zkAPI + mixnet | содержание переписанного запроса |
| **L2** | zkAPI + Tor | + возможная корреляция по времени при сговоре с guard-узлом |
| **L3** | ключ из пула + Tor | + связь разговоров под одним ключом |
| **L4** | прямой доступ | всё; запрещён во всех профилях |

Профиль задаёт минимальный допустимый уровень; классификатор может только поднять
требование (например, `local_only` → L0), но не опустить.

### 4.8 Агенты в песочнице

Как у Виталика: сторонний агент (кодовый ассистент, исследовательский агент)
запускается через `nymwrap run -- <команда>`:

- bwrap/MicroVM с `--unshare-net`; единственная точка связи — unix socket `nw-api`;
- файловая система: только рабочая папка проекта на запись, остальное только на чтение или скрыто;
- переменные окружения `OPENAI_BASE_URL` и аналоги указывают на сокет NymWrap;
- все сетевые запросы агента (поиск, загрузка страниц) идут через Shield;
- окружение агента нормализовано (§4.9.5): он не видит настоящее имя
  компьютера, пользователя, часовой пояс, пути и идентификаторы железа.

### 4.9 Жёсткие данные устройства и окружения

**Жёсткие данные** (hard data) — признаки, которые выдают человека независимо от
того, что он пишет: IP, Wi-Fi и MAC, GPS и геолокация, часовой пояс и часы, язык
и локаль, имя компьютера и пользователя, пути, идентификаторы железа, отпечатки
протоколов, метаданные файлов. Решение и его обоснование — ADR 0043.

Принцип: каждый жёсткий признак закрывается **на самом раннем слое**, где он
появляется, а Shield (`minimize` + `leakcheck`) страхует на уровне текста. Признак
либо отсутствует, либо заменён **общим для всех установок** значением (`UTC`,
`localhost`, `user`, `/work`), чтобы все пользователи NymWrap выглядели одинаково.
Случайное значение на каждую установку само становится идентификатором, поэтому
его не используем.

#### 4.9.1 Сетевой слой

| Признак | Кто видит | Требование |
|---|---|---|
| Домашний/публичный IP | провайдер ИИ, поисковик | теневая полоса выходит только через Tor/Nym (§4.5); IP машины провайдеру недоступен |
| DNS-запросы | провайдер интернета, оператор Wi-Fi | разрешение имён только внутри транспорта; системный DNS-резолвер не вызывается |
| Страна выхода | провайдер ИИ | страна exit-узла не закрепляется (закрепление «своей» страны = утечка местоположения); выбор arti по умолчанию |
| Факт использования Tor | оператор Wi-Fi, школа, провайдер интернета | опциональные мосты: pluggable transports `obfs4`, `snowflake`, `webtunnel` через `tor-ptmgr`; в `paranoid` предлагаются при первом запуске |
| MAC-адрес, имя компьютера в DHCP, mDNS/LLMNR/NetBIOS | оператор локальной сети | NymWrap не меняет настройки ОС; **проверка гигиены** (§4.9.7) читает их и показывает инструкцию |
| IPv6 с MAC внутри (EUI-64) | провайдер ИИ при прямом выходе | прямого выхода нет; IPv6-адреса в тексте маскирует Shield |
| WebRTC, утечки браузера | сайты | в теневой полосе браузера нет; для настоящего сёрфинга UI рекомендует Tor Browser / Mullvad Browser |

#### 4.9.2 Протокольный слой

`nw-netd` строит каждый HTTP-запрос с нуля; ничего из входящего запроса клиента,
кроме проверенного тела, наружу не проходит.

- **Заголовки** — закрытый allowlist: `Host`, `Content-Type`, `Accept`,
  `Accept-Encoding: identity`, `Connection: close`, `Authorization`,
  `Content-Length`, в фиксированном порядке. Отсутствуют: `User-Agent`,
  `Accept-Language`, `Date`, `Cookie`, `X-Stainless-*` (SDK OpenAI отправляет в них
  ОС, архитектуру и версию runtime), любые `X-Forwarded-*`.
- **Тело** — allowlist полей `model`, `messages[{role, content}]`, `temperature`,
  `max_tokens`, `stream`. Поля `user`, `metadata`, `store`, `safety_identifier`,
  `prompt_cache_key`, `seed`, `tools`, `logit_bias`, вложения отвергаются
  (`deny_unknown_fields`), а не тихо удаляются, чтобы клиент знал о них.
- **TLS** — один ClientHello для всех установок и всех ОС: rustls с фиксированным
  набором шифров и групп, ALPN `http/1.1`, без session resumption и 0-RTT, SNI =
  хост провайдера. Отпечаток JA3/JA4 выдаёт «это NymWrap», но не конкретного
  человека: анонимное множество — все пользователи NymWrap. Изменение
  TLS-конфигурации = новая версия golden-теста и запись в ADR.
- **Время в протоколе** — в запросе нет меток времени: TLS 1.3 random не содержит
  времени, заголовка `Date` нет, идентификаторы запросов генерирует CSPRNG.

#### 4.9.3 Слой содержания (Shield)

Новый вид секретов — **секреты устройства** (`SecretKind::Device`). Отдельный
одноразовый процесс `nw-probe` без сети при создании пространства и затем раз в
сутки собирает локальные жёсткие идентификаторы и передаёт их в vault через IPC.
Пользователь видит список и может убрать пункты.

| Собирается | Windows | Linux | macOS |
|---|---|---|---|
| имя пользователя, отображаемое имя | `USERNAME`, `NetUserGetInfo` | `getpwuid` | `getpwuid` |
| имя компьютера, домен | `COMPUTERNAME`, `USERDOMAIN` | `gethostname` | `scutil --get ComputerName` |
| домашний путь во всех формах | `C:\Users\x`, `C:\\Users\\x`, `/c/Users/x`, `/mnt/c/Users/x` | `/home/x` | `/Users/x` |
| MAC-адреса интерфейсов | `GetAdaptersAddresses` | `/sys/class/net/*/address` | `getifaddrs` |
| сохранённые сети Wi-Fi (SSID) | `WlanGetProfileList` | NetworkManager connections | `networksetup -listpreferredwirelessnetworks` |
| локальные IP-адреса | `GetAdaptersAddresses` | `getifaddrs` | `getifaddrs` |
| идентификатор машины | `MachineGuid` | `/etc/machine-id` | `IOPlatformUUID` |
| часовой пояс | имя зоны Windows и IANA, смещение `+04:00`, `UTC+4`, `GMT+4` | `/etc/localtime` | `systemsetup -gettimezone` |
| git-личность | `user.name`, `user.email` из глобального `.gitconfig` | то же | то же |

Секреты устройства блокируются leakcheck во всех уже поддерживаемых кодировках и
транслитерациях, как личные секреты.

Новые детерминированные детекторы в `minimize` (заменяют значение плейсхолдером, а
leakcheck блокирует остаток после модели):

| Детектор | Что ловит |
|---|---|
| `GEO` | пары координат `40.1772, 44.5035` (≥ 3 знаков после точки, в диапазонах широты/долготы), формат `40°10'38"N`, `geo:` URI, `@lat,lon` в ссылках на карты, Plus Codes |
| `MAC` | `aa:bb:cc:dd:ee:ff`, `aa-bb-…`, `aabb.ccdd.eeff` (BSSID Wi-Fi имеет тот же формат) |
| `IMEI` | 15 цифр с проверкой Луна |
| `USER_PATH` | сегмент имени пользователя в `C:\Users\<x>`, `/home/<x>`, `/Users/<x>` — заменяется сегмент, остальной путь сохраняется |
| `TZ` | имена зон IANA (`Asia/Yerevan`) и Windows (`Caucasus Standard Time`), смещения в метках времени (`+04:00`, `+0400`, `GMT+4`) |
| `DATETIME` | точные метки времени с секундами приводятся к UTC с округлением до часа; исходная метка хранится в vault и возвращается в ответе |
| `GUID` | UUID/GUID заменяются плейсхолдером (часто это идентификаторы устройств и аккаунтов) |

Вложения (изображения, документы): до появления локального очистителя метаданных
API их отвергает (fail-closed). Требования к очистителю: изображения
перекодируются без EXIF/XMP/IPTC (GPS, серийный номер камеры, время снимка),
документы превращаются в текст локально и проходят обычный конвейер, исходный
файл и его имя не уходят.

#### 4.9.4 Слой времени

Часовой пояс выдаётся не только текстом, но и **ритмом**: когда приходят запросы
и когда компьютер выключен.

- Режим постоянной скорости (§4.3) скрывает ритм внутри сеанса.
- **Отложенная отправка**: несрочные задания async API (`/v1/nymwrap/chat/jobs`)
  можно пометить `X-NymWrap-Defer: <часы>`; задание уходит в случайный слот в
  этом окне, и время отправки перестаёт совпадать со временем вопроса.
- **Размытые границы сеанса**: первая отправка после запуска откладывается на
  случайные 5–30 минут; при закрытии приложения приманки продолжаются случайные
  10–60 минут, если пользователь согласился держать процесс в фоне.
- Под L3 все запросы одного ключа связаны, и суточный ритм ключа виден
  провайдеру. Под zkAPI (L1/L2) разговоры не связаны, и ритм не складывается.
  Это показывается в UI рядом с уровнем доверия.
- Часы машины наружу не уходят. Проверка гигиены предупреждает о расхождении
  часов больше 5 минут (оно ломает Tor и выделяет клиента).

#### 4.9.5 Окружение агентов и процессов

Агент (`nymwrap run`) пишет в свой системный промпт ОС, версию, рабочую папку,
дату, иногда git-почту. Поэтому окружение песочницы нормализовано до общих
значений, а Shield ловит то, что всё-таки просочилось.

| Признак | Значение внутри песочницы |
|---|---|
| имя компьютера | `localhost` (`--unshare-uts --hostname localhost`) |
| пользователь | `user`, uid/gid 1000, заглушка `/etc/passwd` и `/etc/group` |
| `HOME`, рабочая папка | `/home/user`, `/work` |
| часовой пояс | `TZ=UTC`, `/etc/localtime` → UTC |
| язык и локаль | `LANG=C.UTF-8`, `LC_ALL=C.UTF-8` |
| идентификатор машины | общий фиксированный `/etc/machine-id` для всех установок |
| `/sys` (DMI-серийники, MAC в `/sys/class/net`) | не монтируется |
| D-Bus, GeoClue, NetworkManager, сокеты служб | не монтируются: геолокация и список Wi-Fi недоступны |
| `.gitconfig` пользователя | не монтируется; внутри `user.name=user`, `user.email=user@localhost` |
| переменные окружения | очищаются, задаются только перечисленные |

Windows: агенты в `paranoid` и `strict` запускаются через WSL2 с той же схемой.
AppContainer-процессы NymWrap получают профиль без capabilities `location`,
`wiFiControl`, `bluetooth`, `webcam`, `microphone`. Ни один процесс NymWrap не
вызывает API геолокации.

#### 4.9.6 Полоса легенды

Полоса легенды по замыслу работает от лица настоящего аккаунта, поэтому IP и
местоположение там **не подделываются**: аккаунт и так знает человека, а смена IP
делает аккаунт подозрительным и нарушает инвариант 7.

- Расширение не запрашивает разрешение `geolocation` и не читает местоположение.
- **Дрейф времени активности**: часы активности — часть персоны (урок считает
  `peak_hours`). План легенды задаёт целевое окно активности, и дни легенды
  выполняются внутри окна, которое сдвигается не больше чем на 1–2 часа за этап.
  Так постепенно меняется и представление о том, **когда** человек активен
  (пункт «yerb vonc» из задания).

#### 4.9.7 Проверка гигиены

Экран «Гигиена» читает настройки ОС (только чтение, без прав администратора) и
показывает, что исправить вручную, с инструкцией для конкретной ОС:

- случайные MAC-адреса для Wi-Fi включены;
- имя компьютера не содержит имени человека (`Davit-PC` → `DESKTOP-01`);
- LLMNR, NetBIOS и mDNS выключены для публичных сетей;
- службы геолокации выключены для настольных приложений;
- часы синхронизированы (расхождение < 5 минут);
- WebRTC и геолокация запрещены в браузере, где пользователь сёрфит по-настоящему.

Результат хранится зашифрованным и учитывается в метрике `hygiene_score`.

## 5. Интерфейсы

### 5.1 OpenAI-совместимый API (`nw-api`)

- Основной транспорт: unix socket `$XDG_RUNTIME_DIR/nymwrap/api.sock` (права 0600)
  или named pipe `\\.\pipe\nymwrap-api` с ACL текущего пользователя.
- Опционально TCP `127.0.0.1:<random>` с bearer-токеном из файла 0600, проверкой
  заголовка `Host` (защита от DNS rebinding, как в `app.py` урока), без CORS.
- Эндпоинты: `POST /v1/chat/completions`, `POST /v1/embeddings`, `GET /v1/models`.
- Расширения через заголовки: `X-NymWrap-Conversation: new|<id>`,
  `X-NymWrap-Min-Trust: L0..L3`, `X-NymWrap-Lane: shadow` (единственное допустимое значение для этого API).
- Модели в `/v1/models` имеют вид `nw/<provider>/<model>` и `nw/local/<model>`.

### 5.2 IPC

Все сообщения в `nw-proto`: `enum Msg { ShieldRequest, ShieldResponse, NetSend, NetResult, DriftTask, DriftResult, AuditImport, ... }`,
у каждого поле `lane`. Core отвергает сообщение, если `lane` не совпадает с полосой
процесса-отправителя (полоса процесса фиксирована при запуске).

### 5.3 Конфигурация

`~/.config/nymwrap/config.toml` (Windows: `%APPDATA%\NymWrap\config.toml`).
Секретов в конфиге нет, только ссылки на хранилище ключей ОС.

```toml
profile = "strict"                # standard | strict | paranoid

[shield]
min_trust = "L2"
translate_to_english = true
show_diff_before_send = true
max_turns_per_conversation = 12
secrets_list = "vault:secrets"    # личный список, хранится в vault

[cover]
mode = "poisson"                  # poisson | constant
mean_interval_s = 600
max_requests_per_day = 60
max_spend_per_day_usd = 0.50

[net]
transport = "tor"                 # tor | nym
bridges = "none"                  # none | obfs4 | snowflake | webtunnel

[hard]
device_secrets = true             # nw-probe собирает секреты устройства
defer_max_hours = 0               # окно отложенной отправки по умолчанию
session_tail_minutes = [10, 60]   # приманки после закрытия, если разрешён фон
attachments = "reject"            # reject | scrub (после реализации очистителя)

[drift]
mode = "assisted"                 # assisted | extension
days_per_stage = 5
stages = 10
min_hours_between_days = 12

[llm]
backend = "llama.cpp"
model = "qwen3:8b"
embed_model = "nomic-embed-text"
```

## 6. Модуль Drift (полоса легенды)

Развитие урока `anti-persona` с поправками из его `ROADMAP.md`.

### 6.1 Поток

1. **Research** (`nw-audit`): импорт Google Takeout (поиск, YouTube, Chrome со всех
   устройств), истории браузеров, официальных экспортов ChatGPT/Claude/Gemini.
   Агрегация локально; модели уходит только сводка (домены, заголовки, поиски,
   часы активности, ключевые слова, 30 образцов промптов) — как в `persona.py`.
2. **Persona**: локальная модель строит персону с доказательствами. Пользователь
   отмечает каждую черту «это я / не я»; план строится только на подтверждённых.
3. **Cover**: пользователь выбирает легенду — шаблон («садоводство и природа»,
   «история и музеи», «кулинария»…), свою формулировку или зеркальную анти-персону
   из урока. Легенда проходит фильтр безопасности (§6.4).
4. **Plan**: этапы с правилом моста и правилом темпа, проверка эмбеддингами — без
   изменений по математике урока (README урока, раздел «The math»): ось
   `t(e) = (cos(e,a) − cos(e,p)) / (2·(1 − cos(p,a))) + 0.5`, проверки соседства,
   максимального шага, откатов и покрытия; до 3 попыток с обратной связью модели.
5. **Approve**: пользователь читает план; одобрение привязано к хешу этапов и к
   списку затрагиваемых сервисов (как `approval_id` в `anti.py`).
6. **Execute** в аккаунтах пользователя:
   - `assisted` (по умолчанию): каждый день UI показывает 5–10 действий
     («поищи…», «посмотри видео про…», «спроси у ИИ…»), человек делает их сам;
     расширение отмечает выполнение.
   - `extension`: расширение выполняет действия в настоящем браузере в отдельной
     вкладке, в человеческом темпе (печать 60–180 мс на символ, чтение 20–90 с).
   - Один день не чаще раза в 12 часов, этап длится `days_per_stage` дней, каждый
     день формулировки переписываются заново (как `variants.json` в уроке).
   - День выполняется внутри окна активности этапа, которое постепенно сдвигается
     от часов персоны к часам легенды (§4.9.6).
7. **Measure**: см. модуль Mirror; темп этапов подстраивается по реальной ленте
   (замкнутый контур: если лента отстаёт от плана, следующий этап задерживается).

### 6.2 Память ИИ-сервисов

Порядок методов — от самого честного к наименее желательному:

1. **Удалить**: старые чаты, сохранённые воспоминания, отключить обучение на
   своих данных (модуль Purge генерирует пошаговый план под каждый сервис).
2. **Отредактировать**: Drift готовит текст для пользовательских инструкций и
   правок памяти в духе легенды; пользователь вставляет его сам.
3. **Разговоры легенды**: промпты этапа для ИИ-сервиса; в `assisted` человек
   вставляет их сам. Автоматизация веб-интерфейсов ChatGPT/Claude/Gemini нарушает
   их условия, поэтому она выключена и включается только явно, с предупреждением
   о риске блокировки аккаунта.
4. **Все будущие реальные вопросы** к ИИ идут через Shield, а не через
   потребительское приложение под своим аккаунтом, поэтому новые реальные данные в
   память аккаунта не попадают.

Честное ограничение: то, что уже попало в обучающие данные моделей, программа
убрать не может; меняется только персонализация, память и рекламный профиль.

### 6.3 Правила исполнения

- Расширение не видит теневую полосу: у него нет доступа к vault, реальной истории
  и Shield. Оно получает только `DriftTask` с текстом легенды.
- CAPTCHA, проверка «вы робот?» или страница входа останавливают выполнение и
  передают управление человеку; программа их никогда не обходит.
- Без маскировки автоматизации: никаких подмен отпечатка браузера и флагов против
  обнаружения ботов (урок признал их репутационным риском в ROADMAP).
- Журнал действий легенды (`cover_log`) хранится отдельно от теневых данных и
  шифруется своим ключом.

### 6.4 Фильтр легенды

Легенда и каждое действие проходят фильтр до одобрения плана:

- запрещены: экстремизм, самоповреждение, расстройства пищевого поведения,
  наркотики, оружие, азартные игры, всё незаконное;
- темы «здоровье, религия, политика, сексуальность, финансовое положение» требуют
  отдельного согласия: они меняют то, как с человеком обращаются (страховки,
  кредиты, реклама), и могут навредить ему самому;
- легенда не выдаёт себя за реального другого человека и не предназначена для
  обмана банков, работодателей, госорганов.

## 7. Модули Purge и Mirror

### 7.1 Purge — уменьшение старого

- **Выборочное удаление по силе сигнала**: по модели персоны Purge ранжирует
  элементы истории (поиски, просмотры YouTube, чаты) по тому, насколько сильно
  каждый подтверждает текущую персону (позиция на оси около 0 и высокая частота),
  и предлагает удалить сначала их. Нейтральные элементы остаются, чтобы профиль не
  выглядел «стёртым».
- **Автоудаление**: пошаговые инструкции включить автоудаление активности (Google
  My Activity, YouTube), отключить персонализацию рекламы, удалить память ИИ.
- **Запросы на удаление данных**: шаблоны писем по праву на доступ и удаление
  (GDPR ст. 15 и 17 и аналоги местного законодательства) с полями, заполняемыми
  локально.
- Purge ничего не удаляет сам без подтверждения каждой партии.

### 7.2 Mirror — что обо мне думают

| Снимок | Как получаем |
|---|---|
| Рекламные темы Google (My Ad Center) | пользователь открывает страницу, расширение читает список тем (только чтение) |
| Главная лента YouTube | расширение раз в день сохраняет заголовки первых 30 карточек |
| Подсказки поиска | расширение сохраняет подсказки для набора нейтральных префиксов |
| Память ИИ | раз в неделю в полосе легенды: «что ты обо мне знаешь?»; в `assisted` человек вставляет вопрос и ответ |
| Новый Takeout | повторный импорт раз в месяц |

Каждый снимок превращается в эмбеддинги и получает позицию на оси «персона →
легенда».

### 7.3 Метрики

| Метрика | Смысл | Цель |
|---|---|---|
| `feed_position` | позиция ленты YouTube на оси | растёт по плану |
| `ad_topics_position` | позиция рекламных тем | растёт по плану |
| `ai_memory_position` | позиция ответа ИИ «что ты обо мне знаешь» | ≥ 0.6 к концу плана |
| `shadow_share` | доля реальной активности, ушедшей в теневую полосу | как можно выше; ниже 50% дрейф идёт медленно |
| `leak_blocks` | сколько запросов заблокировал leakcheck | видно пользователю, растущий тренд = проверить секреты |
| `cover_ratio` | приманки / реальные запросы | по профилю |
| `challenge_rate` | остановки на CAPTCHA и входе | 0 |
| `plan_checks` | соседство, шаг, откаты, покрытие из урока | все выполнены |
| `hygiene_score` | доля выполненных пунктов проверки гигиены (§4.9.7) | 100% |
| `hard_blocks` | сколько запросов остановили детекторы жёстких данных и секреты устройства | видно пользователю по видам, без значений |

## 8. Профили

| Настройка | standard | strict | paranoid |
|---|---|---|---|
| минимальный trust level | L3 | L2 | L1 (L0 при недоступности mixnet) |
| транспорт | tor | tor | nym, иначе tor |
| cover-трафик | пуассон, редко | пуассон | постоянная скорость |
| перевод на английский | выкл | вкл | вкл |
| дифф перед отправкой | выкл | вкл | вкл, обязательно |
| split | выкл | по запросу | вкл для длинных задач |
| ходов в разговоре | 30 | 12 | 6 |
| песочница | процессы ОС | bwrap / AppContainer | MicroVM для агентов, bwrap для демонов |
| журналы | только события | только события | только счётчики |
| секреты устройства | вкл | вкл | вкл |
| мосты Tor | выкл | по выбору | предлагаются при запуске |
| отложенная отправка по умолчанию | 0 ч | 0 ч | до 2 ч для async |
| хвост сеанса | выкл | по согласию | по согласию |
| нормализация окружения агентов | вкл | вкл | вкл |
| платформа | любая | любая | рекомендуется Linux |

Ожидаемая цена `paranoid`: заметная задержка (особенно на первом запросе нового
разговора, как пишет Виталик) и расход бюджета на приманки.

## 9. Этапы разработки

Каждый этап закрыт, только когда все его критерии приёмки зелёные в CI.

| Этап | Содержание | Критерии приёмки |
|---|---|---|
| **M0 Прототип** | обёртка вокруг кода урока: Shield без сети (minimize + canonicalize + leakcheck + rehydrate) поверх Ollama | 100 канареек в тестовых промптах — ни одна не проходит leakcheck; круговой тест rehydrate восстанавливает исходные значения |
| **M1 Ядро** | Rust-workspace, `nw-proto`, `nw-vault`, `nw-shield`, `nw-llm`, `nw-api` с локальной моделью (L0) | OpenAI-клиент работает через unix socket; все данные на диске зашифрованы (тест: поиск открытого текста в файлах данных находит 0 совпадений) |
| **M2 Сеть** | `nw-netd` с arti, изоляция по разговорам, fail-closed, network namespaces | тест: core в своём namespace не может открыть внешний сокет; при остановке Tor запрос падает с ошибкой и ничего не уходит напрямую; два разговора — две разные цепочки |
| **M3 Cover** | `nw-cover`, режимы пуассон и постоянной скорости, бюджет | по захвату трафика на выходе `nw-netd` длины запросов лежат только в корзинах; бюджет не превышается за симулированные 7 дней |
| **M3H Жёсткие данные** | §4.9: `nw-probe` и секреты устройства, детекторы GEO/MAC/IMEI/USER_PATH/TZ/DATETIME/GUID, нормализация окружения агентов, мосты, отложенная отправка, хвост сеанса, проверка гигиены, окно активности легенды | канарейки из каждого вида секретов устройства и каждого детектора не появляются в захвате на границе `nw-netd`; golden-тест: байты заголовков и ClientHello (кроме random и key share) совпадают на Windows и Linux; агент в песочнице видит `hostname=localhost`, `TZ=UTC`, `LANG=C.UTF-8`, `/work`, общий machine-id и не может прочитать `/sys`, D-Bus и настоящий `.gitconfig`; запрос с вложением получает отказ |
| **M4 Audit + Purge + Mirror** | импортеры, ранжирование по силе сигнала, снимки | импорт тестового Takeout воспроизводимо даёт одну и ту же сводку; шаблоны удаления генерируются без сети |
| **M5 Drift** | планировщик из урока на Rust, расширение, режим `assisted` | тесты математики оси совпадают с `anti.py selftest`; расширение останавливается на тестовой странице с CAPTCHA |
| **M6 Укрепление** | профили песочниц, seccomp, MicroVM для агентов, подписанные сборки | чек-лист THREAT_MODEL §9 выполнен полностью |
| **M7 Эксперимент** | `nym`-транспорт, адаптер zkAPI | за флагами, документировано как экспериментальное |

## 10. Тестирование

- **Канареечные тесты утечек** (`tests/leak/`): в vault и в промпты подкладываются
  уникальные строки; весь трафик на границе `nw-netd` записывается; любая
  канарейка в записи (в т.ч. в base64, транслитерации, с разбиением пробелами) =
  провал.
- **Тесты выхода**: каждый процесс, кроме `nw-netd`, запускается в песочнице, и
  тест пытается открыть сокет наружу — ожидается отказ.
- **Fail-closed**: остановка транспорта посреди потока ответа не приводит к
  повторной отправке другим путём.
- **Детерминизм**: этапы с моделью тестируются при temperature 0 и закреплённой
  модели; корректность гарантирует leakcheck, а не модель.
- **Property-тесты**: `rehydrate(minimize(x)) == x` для произвольного текста.
- **Фаззинг**: парсеры импортеров и IPC (`cargo fuzz`).
- **Безопасность UI**: всё недоверенное (заголовки страниц, ответы моделей)
  экранируется; тест с `<script>` в заголовке.
- **Жёсткие данные**: синтетические секреты устройства (имя ПК, SSID, MAC, путь,
  часовой пояс, machine-id, git-почта) подкладываются в системный промпт агента и в
  обычные вопросы; ни один не появляется в захвате. Тест протокольного отпечатка
  сравнивает заголовки и ClientHello с golden-файлом на каждой ОС CI.
