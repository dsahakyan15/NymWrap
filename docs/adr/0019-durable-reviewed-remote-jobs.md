# Сохраняемые удалённые задания после одноразового одобрения

## Решение

StartRemoteJob принимает capability просмотра один раз и сразу возвращает id.
Одобренный turn держит резервацию разговора в памяти, исходные сообщения и ответ
хранятся в ShadowHistory, индекс из не более 64 id/статусов/времён/кодов — в Vault.
Текст не попадает в журналы или CoverLog. Передача capability другому Engine
запрещена. После приёма одобрения модель не вызывается повторно.

Исполнение делает обычный Route. После сохранения аренды ключа и верхней оценки
расходов, перед send, задание становится Sending. Done появляется только после
сохранения ответа и истории. Ошибка после Sending — Uncertain, до него — Blocked;
transport/session errors также консервативно считаются Uncertain. Автоповторов нет.
Интерфейс опрашивает id вместо удержания одного долгого RPC и позволяет отмену.
Отмена Sending не отзывает уже ушедшие байты и не возвращает бюджет.

Смена epoch отменяет задачи. После перезапуска Queued/Sending превращаются в
Uncertain: старая capability не восстанавливается. Человек может вернуть исходные
сообщения в новый разговор, заново пройти проверки и просмотр. Очистка истории
убирает также сохранённые исходные сообщения/ответы заданий; метаданные переходят
в Expired при чтении. При Lock UI прекращает опрос и не запускает новый core
через устаревшую команду отмены.

## Проверки и границы

Тест проверяет зашифрованные исходные сообщения, сохранение результата, восстановление
Uncertain без вызова remote и очистку вместе с ShadowHistory. Opt-in E2E использует
настоящий Tor/TLS и синтетический ключ: терминальная ошибка резервируется один раз,
повтор nonce запрещён, kill core оставляет неопределённое задание и его исходный
текст без повторного send. Никакой платный аккаунт тест не использует.

Диспетчер постоянных слотов описан в ADR 0020, отдельный async HTTP endpoint —
в ADR 0021. В standard/Poisson задания исполняются сразу, в Constant ждут слот.
Новых зависимостей нет.
