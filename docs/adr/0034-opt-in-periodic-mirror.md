# Ежедневный Mirror в расширении по явному включению

## Решение

Расписание выключено по умолчанию. Кнопка popup запрашивает optional host
permissions только для https://www.youtube.com/* и https://youtube.com/*.
Разрешение не выдаётся установкой расширения. Фоновый обработчик принимает
изменения настроек только от собственного popup, не от страниц/content scripts.

Chrome использует MV3 module service worker; Firefox — module background scripts.
Сборщик создаёт отдельные manifest. Используются штатные alarms/storage APIs,
без зависимостей, сетевого клиента, content script или таймеров keep-alive.
Официальные схемы: [Chrome alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms),
[Firefox background](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background).

Почасовой alarm ищет уже открытую главную YouTube. Не открываются вкладки,
не выполняются переходы, запросы поиска, воспроизведение или логин. Приватные
вкладки пропускаются. До чтения проверяется разрешение и состояние ядра/паузы;
после чтения они проверяются снова. URL проверяется также внутри фиксированного
DOM reader: навигация между tabs.query и executeScript не расширяет allowlist.
Снимаются максимум 30 заголовков, без адресов ссылок или тела страницы в IPC.
Заголовки проходят обычную схему Snapshot и локальные embeddings, хранятся
зашифрованными в Metrics. Расширение не получает shadow-данные.

На диске расширения остаются только публичная настройка enabled и содержательно
пустая запись события: время попытки, время успешного сохранения и код состояния.
Текст/URL/снимок/задания/секреты туда не записываются. Это тот же класс публичных
настроек и журналов событий, что config.toml и THREAT_MODEL §5. Перед чтением
резервируется суточная попытка; потерянный ACK, рестарт worker и откат часов не
разрешают повтор в эти сутки. Пропущенные периоды не догоняются. Ошибка требует
ручного снимка либо ожидания следующих суток; отсутствие вкладки/открытого ядра
не расходует попытку чтения.

CAPTCHA/login выключают расписание до ручного включения, даже если core
отключился. SafetyStop получает только случайный id и причину. Отзыв host
permission также выключает расписание. Отключение во время чтения не даёт
отправить его результат. Уже начатое сохранение нельзя отозвать.

## Проверки и границы

Тесты исполняют scheduler и DOM reader: opt-in/allowlist, отсутствие DOM-доступа
при pause/lock/revocation, гонку отключения, restart/lost ACK/clock rollback,
суточный лимит, CAPTCHA/login и отсутствие текста в storage. Отдельно проверяются
обе сборки manifest и сообщения фонового обработчика. Проверка с настоящими
Chrome/Firefox, локальной моделью и реальной главной YouTube остаётся отдельной.
Автоматические Ad Center/подсказки и недельная память ИИ этим решением не включены.
