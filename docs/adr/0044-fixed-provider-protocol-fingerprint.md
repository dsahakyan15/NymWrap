# Закреплённый отпечаток HTTP и TLS провайдера

## Решение

Только provider TLS в `nw-netd` использует фиксированный профиль: ring, явно
перечисленные шифры TLS 1.3/1.2 и группы X25519/P-256, ALPN http/1.1, без
resumption, early data, сжатия сертификатов и key logging. Верификация WebPKI и
SNI остаются обязательными. Arti не получает provider-конфигурацию.

В rustls 0.23.46 порядок расширений ClientHello случайный. Для требования
SPEC §4.9.2 закреплена локальная копия `vendor/rustls`: единственная функциональная
правка добавляет `ClientConfig::extension_order_seed: Option<u16>` (по умолчанию
`None`) и применяет `Some(0)` только к порядку расширений provider ClientHello.
Генератор случайных чисел, key exchange, проверка сертификатов, session IDs и
client random не меняются. Подмена RNG ради предсказуемого теста отвергнута.
Исходный архив — crates.io rustls 0.23.46; его SHA-256 закреплён в
`vendor/rustls/NYMWRAP-PATCH.md`. Локальная копия используется только отдельным
workspace nw-netd; её содержимое входит в source SBOM. Обновление требует нового
аудита патча, cargo-deny и намеренного обновления golden.

Golden TLS сравнивает реальные байты rustls: обнуляет только client random,
случайный legacy_session_id и публичные key shares (сохраняя длины и группы).
Другие байты, включая порядок расширений, SNI и ALPN, должны совпасть между
сеансами и ОС. Golden HTTP сравнивает байты настоящего Hyper serializer с
синтетическим authorization; не сортирует заголовки перед сравнением.

Это проверка протокола до сети. Она не заменяет pcap на ОС, проверку маршрутов,
корреляции времени или зелёный CI на каждой платформе.
