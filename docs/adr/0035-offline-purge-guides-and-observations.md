# Инструкции Purge и ручное наблюдение результата

## Решение

Для пяти Service поставляются отдельные инструкции с датой проверки и адресами
официальной справки. Они встроены в nw-purge, доступны без модели и сети. UI
показывает адреса текстом для копирования в свой браузер; WebView не переходит
на внешние страницы. Ничего не удаляется и не отправляется автоматически.

Результат партии — ручное наблюдение пользователя: ещё не проверено, записи
больше не видны, ещё видны либо проверка недоступна. Исчезновение из интерфейса
не объявляется доказательством уничтожения серверных копий. Отдельно отмечаются
шаги истории, памяти, хранения, приватности и повторной проверки по инструкции
конкретного сервиса.

Core принимает результат только для существующей партии с проверенным хешем
одобрения. Список шагов проверяется по стабильным id инструкции, повторы и чужие
шаги отклоняются. Для «больше не видны» обязательны history и verify. Время
ставит core, с округлением до минуты. Результат хранится с отдельным id в том же
зашифрованном домене Imports; повторное одобрение партии его не сбрасывает.
Очистка Imports удаляет и партии, и результаты. Старые партии Batch читаются
без миграции как ещё не проверенные. UI показывает до 100 последних партий.

Новые типизированные команды доступны только shadow RPC; cover/native протокол
не расширен. При блокировке данные исчезают из UI; поздний ответ старой сессии
не восстанавливает их. В браузерное/локальное хранилище UI ничего не записывается.
Зависимости и инварианты не меняются.

## Проверки

Core проверяет отсутствие одобрения, неизвестные/повторные шаги, неполное
подтверждение, повторное одобрение, reopen и crypto-shredding. UI-тест исполняет
рендер с XSS-текстом и проверяет, что отметки сохраняются только кнопкой.
E2E проходит настоящий RPC, создание/одобрение партии и повторное открытие.
