# Экспериментальный клиент zkAPI без открытого маршрута

Принято 2026-11-26, продолжает ADR 0024 и 0090. Флаг
`experimental-zkapi` выключен по умолчанию в `nw-net`, `nw-core`, `nw-netd`
и leak-тестах. Он добавляет клиентский протокольный адаптер, но **не рабочую
защиту**: upstream zkAPI не развёрнут. Ни L1, ни L2 не доступны в выпуске.

## Граница и допуск

Закреплён upstream
[`0fb263b0da04986cfe5c63b12340c1581018ae9b`](https://github.com/vbuterin/zkapi/blob/0fb263b0da04986cfe5c63b12340c1581018ae9b/zkapi-clientd/docs/LOCAL_PROTOCOL_MIGRATION.md):
обе сети `not_deployed`, production ceremony assets отсутствуют. HTTP-ответ,
`/healthz` и заголовок `verified` не доказывают deployment, анонимность оплаты
или отсутствие последующего переписывания моделью. Финансовые операции,
upstream daemon с собственной сетью и dev proving keys не подключаются.

В feature-сборке `keyring:experimental-zkapi` выбирает кандидата zkAPI+Tor
(L2) либо, дополнительно с `experimental-nym`, zkAPI+Nym (L1). Это имена
**кандидатов**, не доказанные фактические уровни. Используются существующие
ворота ADR 0090: профиль, требуемый уровень, индивидуальное одобрение,
одноразовое окно слота. Paranoid принимает только L1, strict — L1/L2.
Независимый `check_available` закрыт константно; он проверяется до показа
одобрения и повторно при принятии одобрения, перед очередью и отправкой.
До расхода ключей, бюджета, bootstrap и передачи тела выполнение не доходит.
Fallback к L3 или прямому соединению отсутствует; L0 для чувствительного
содержания сохраняется. В обычной сборке эта credential-ссылка не принимается.
Существующий Tor send дополнительно принимает только `keyring:pool`: изменение
одного availability gate не может превратить кандидат L2 в отправку через L3.

Только `nw-netd` содержит клиентский HTTP-код. Адаптер получает готовый поток
и числовой loopback authority; DNS, TCP connector, поиск сервиса, CLI/env
переключатель и включение в production factory не добавлены. Тест открывает
синтетический сервер на `127.0.0.1:0`; никакой внешний сервис не вызывается.
Будущий внешний connector должен остаться внутри nw-netd и пройти отдельную
проверку deployment, IPC, изоляции разговоров, хранения и последнего model-stage.

## Контракт и проверки

По закреплённому
[`internal/server/server.go`](https://github.com/vbuterin/zkapi/blob/0fb263b0da04986cfe5c63b12340c1581018ae9b/zkapi-clientd/internal/server/server.go)
используется только `POST /v1/chat/completions`, bearer локального API длиной
не менее 32 графических ASCII-символов и существующее строгое chat-тело:
`model`, `messages`, `temperature: 0`, `max_tokens`, `stream: false`.
Идентификатор разговора и пользовательские заголовки не передаются. Тело
сохраняет корзины длины. Ответ ограничен 1 MiB, только JSON и один assistant
text; tools/function calls запрещены. Требуется ровно один
`X-OA-Verification-Status: verified`, detail/fallback отвергается. Нет
redirect/retry; неопределённый исход не повторяется. Этот заголовок — лишь
проверка протокола, а не основание открыть availability gate.

Последний вызов модели остаётся внутри Engine: итоговый текст и transcript
проверяются leakcheck, включая повторную проверку при одобрении. После этой
границы адаптер только детерминированно сериализует проверенные байты. Реальный
zkapi-clientd пока не запускается: его необследованное downstream rewrite
нельзя поставить после нашего leakcheck и назвать безопасным.

`tests/leak/src/netd_zkapi.rs` проверяет реальные HTTP-байты локального сервера,
канарейку и повторное внедрение секрета последней моделью в шести представлениях
(plain/base64/hex/percent/Unicode escapes/с пробелами),
ошибки, EOF, redirect, неподтверждённый/fallback-ответ и недоверенные действия.
`experimental_queue.rs` проверяет связь с допуском ADR 0090 без keyring/сети;
`tests/leak/tests/paranoid.rs` — отсутствие ложного L1/L2-одобрения и доступность
L0. Feature-тесты включены в CI отдельно от обычной сборки.

Новые зависимости и изменения четырёх Cargo.lock не требуются. M7 не объявляется
завершённым до проверок в CI; deployment, финансовый цикл и реальный L1/L2
остаются открытыми независимо от зелёных синтетических тестов.
