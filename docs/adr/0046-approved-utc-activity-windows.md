# Окно активности легенды входит в одобрение

## Решение

Новые планы содержат `activity.windows`: одно окно на этап, начало в часах UTC,
длительность 1–12 часов. Исходное и целевое начало и длительность задаёт человек
при подготовке плана. UI показывает окна до одобрения. Нейтральный исходный
вариант — 12:00–18:00 UTC, без сдвига; это видимый редактируемый выбор, не вывод
о часах человека из импорта с неизвестным часовым поясом.

Core строит расписание детерминированно по кратчайшему направлению вокруг суток;
изменение начала не больше двух часов за этап, ширина постоянна. Если заданный
переход нельзя уложить в число этапов, запрос отклоняется. Модель не выбирает
расписание и не получает эти параметры. Время браузера, IP и геолокация не
подменяются.

Расписание сериализуется в Plan и входит в его хеш. Новое время требует нового
одобрения плана и дневных вариантов. Core проверяет окно при выдаче задач и
при отметке выполнения, включая повторную проверку существующего search permit.
Переход через полночь допустим; начало включено, конец исключён. Активный день
не разрешает исполнение за пределами окна. Действия не догоняются автоматически.
Проверки 12-часового промежутка, Mirror и конечного leakcheck сохраняются.

Для прежних зашифрованных планов `activity=None` не сериализуется, поэтому
существующий хеш и одобрение не меняются при открытии. UI помечает отсутствие
окна; для получения окна пользователь перестраивает и заново одобряет план.
Новые планы core всегда получают расписание, даже если старый API-клиент не
передал опциональные параметры. Зависимостей не добавлено.
