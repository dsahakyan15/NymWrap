# Полный development-прогон в CI

Последовательные 384 разговора с настоящими 7B ответами и отдельной атакой могут
не уложиться в предел задания GitHub Actions. Восемь заданий получают непересекающиеся
индексы разговоров по 48 случаев. Один разговор и его накопленная история всегда
выполняются целиком в одном процессе. Пороги, модель и параметры между частями
не меняются.

Бинарники release один раз собираются и проходят native CPU smoke. Официальные
actions/upload-artifact и actions/download-artifact закреплены SHA; checksum
проверяется после скачивания. Это даёт одинаковые бинарники всем частям,
но не доказывает воспроизводимость сборки M6. Модели каждая часть получает по
прежним pinned hashes; локальные аккаунты и API-ключи не используются.

CLI --shard i/n выдаёт только complete_shard; его нельзя подать в статистическую
приёмку как complete. Объединение требует все индексы ровно один раз, точные
диапазоны и порядок случаев, одинаковые provenance, policy и CI run/commit.
Пропуск, дубль, partial/failed, чужой бинарник, политика или попытка взять данные
из другого запуска отвергаются. Объединённый отчёт хранит SHA всех исходных частей
и проходит обычную проверку development-качества. Частично зелёные задания этап
не закрывают. Pilot из одного случая также остаётся диагностикой.

Добавлена закреплённая версия actions/download-artifact v8.0.2,
SHA 9000827ccba6bdab643e8b6fd33ac0654aef8333, официальный репозиторий
[actions/download-artifact](https://github.com/actions/download-artifact/tree/9000827ccba6bdab643e8b6fd33ac0654aef8333).
Новые Rust/Node зависимости не вводятся. Held-out этим workflow не создаётся:
сначала требуется законченная development-оценка и заморозка.
