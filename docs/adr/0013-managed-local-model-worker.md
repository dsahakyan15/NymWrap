# Запуск проверенной локальной модели из интерфейса

## Решение

Зашифрованная LlmConfig может содержать абсолютные пути chat/embed GGUF и SHA-256
обоих файлов. Пустые поля сохраняют возможность внешнего приватного сервера.
Команда StartModel запускает только соседний `nw-llmd`, без shell и пользовательских
аргументов. Окружение очищается, логи и stdout отключены, путь и хеш передаются
явными отдельными аргументами. Две конкурентные загрузки сериализуются.

Демон модели проверяет файлы до native parser, грузит их без mmap и проверяет
повторно. Core дожидается приватного IPC и сверяет PID дочернего процесса; чужой
уже занятый endpoint не захватывается. Изменение LlmConfig останавливает старую
управляемую модель, чтобы её нельзя было выдать за новый указанный хеш.

В режиме `--parent-stdio` stdin служит только каналом жизни родителя. EOF или
неожиданный байт завершает процесс, в том числе во время загрузки. Core также
использует kill_on_drop. Lock закрывает workspace и управляемые модели; новый
запуск выполняется кнопкой пользователя. Неуправляемый сервер не уничтожается.

## Компромисс

Перезагрузка GGUF после блокировки занимает время. Это освобождает native-контекст
модели вместе с runtime-сессией, вместо сохранения процесса без владельца.
Проверка SHA-256 и seccomp не заменяет файловую песочницу и AppContainer из M6.
