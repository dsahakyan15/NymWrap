# 0002. Постоянное хранилище и локальный IPC

Статус: принято. Дата: 2026-11-22.

Продолжение M1 использует стек SPEC: rusqlite 0.43.0 с bundled SQLCipher и
vendored OpenSSL. Обычный SQLite не используется для пользовательских записей.
Каждый домен имеет отдельную БД и случайный ключ; SQLCipher проверяется по
cipher_version при открытии, temp_store=MEMORY, журналирование содержимого
выключено. SQL-запросы с данными параметризованы. Содержимое дополнительно
запечатывается XChaCha20-Poly1305 ключом домена до передачи SQLCipher.

keyring 3.6.3 обращается к Windows Credential Manager (защищён DPAPI), macOS
Keychain или Linux Secret Service. Тесты используют отдельный in-memory backend;
настоящий backend никогда не заменяется plaintext-файлом или mock автоматически.
Отсутствие системного keychain — ошибка открытия. Пароль обязателен для strict и
paranoid; в standard пустой пароль допустим, ключ ОС всё равно обязателен.

Корневой файл содержит только технический заголовок (salt, случайный ID ключа)
и зашифрованный keyring. Его обновления проходят через запись нового шифротекста,
fsync и атомарную замену в той же папке. Удерживается межпроцессная блокировка.
При crypto-shredding меняются корневой секрет ОС и мастер-ключ, затем старый
секрет ОС удаляется. Зашифрованный журнал незавершённой очистки позволяет
восстановиться после сбоя; успех не возвращается до завершения очистки.
Резервные копии всего хранилища ОС, swap и физическое стирание SSD остаются
ограничениями THREAT_MODEL: приложение не обещает уничтожения чужих backup.

interprocess 2.4.9 предоставляет Unix sockets и Windows named pipes без TCP.
Windows ACL задаётся явным security descriptor только для владельца объекта.
widestring 1.2.1 нужен для безопасной передачи SDDL. Полоса фиксируется на
отдельном endpoint. При подключении к API клиент не может выбрать endpoint
теневых данных через сообщение легенды. toml 1.2.2 — строгая конфигурация без
секретов. Все версии и транзитивные контрольные суммы закрепляются lock-файлами.

Источники: [SQLCipher API](https://www.zetetic.net/sqlcipher/sqlcipher-api/),
[rusqlite](https://docs.rs/rusqlite/0.43.0/),
[keyring](https://docs.rs/keyring/3.6.3/),
[interprocess](https://docs.rs/interprocess/2.4.9/).
# Проверка лицензий

Для закреплённых транзитивных зависимостей interprocess разрешён 0BSD
(`doctest-file` 1.1.1, `recvmsg` 1.0.0). Для `sqlcipher-src` 420.0.0 разрешены
SQLite blessing (публичное достояние) и WTFPL встроенных компонентов; MIT и
BSD-3-Clause уже разрешены политикой. Исключения ограничены этими пакетами и
версиями, общий список разрешений не расширяется.
