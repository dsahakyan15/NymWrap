# Изолированный импорт и системный запрет IP-сокетов

## Решение

Демон передаёт импорт анонимной трубе `nw-audit-worker`. Процесс получает формат
и не более 8 MiB исходных байтов; имена файлов, vault, настройки и модель ему
не передаются. Один импорт — один процесс; таймаут 30 секунд, выход не более
4 MiB. Выходная сводка повторно проверяется ядром. Отмена запроса убивает процесс.

На Linux worker запускается через bwrap: отдельные namespaces, без домашней
директории и доступных для записи путей хоста. Ошибка запуска песочницы не
включает обработку в основном процессе. Остальные платформы используют отдельный
процесс с очищенным окружением; полноценный AppContainer остаётся требованием M6.

Linux core, API, модель и импорт включают seccomp TSYNC для всех потоков. Разрешён
AF_UNIX; у core дополнительно разрешён NETLINK_ROUTE для настройки loopback
дочернего bwrap в новой netns. В worker остаётся только AF_UNIX. TCP/UDP и прочие
семейства отвергаются EPERM. Закрыты io_uring,
ptrace, process_vm, bpf и userfaultfd. Worker после запуска bwrap дополнительно
закрывает операции смены namespace и монтирования; родитель сохраняет возможность
запустить bwrap для следующего импорта. x32 ABI на
x86_64 отвергается. clone3 отвечает ENOSYS для штатного перехода libc к clone.
Это дополняет bwrap и не заменяет ограничения файлов и запуска агентов.

## Проверка

Отдельный тестовый процесс пытается открыть TCP и UDP сокеты и ожидает EPERM;
пара UnixStream продолжает работать. Тест изолирован от основного тестового
раннера, поскольку seccomp наследуется и не может быть снят.
