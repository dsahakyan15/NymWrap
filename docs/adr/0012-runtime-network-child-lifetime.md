# Жизненный цикл ядра и сетевого процесса

## Решение

До открытия пространства ядро запускает только соседний установленный `nw-netd`
(в debug также каталог его сборки). У дочернего процесса нет конфигурации маршрута
и он не обращается в сеть: bootstrap требует отдельной аутентифицированной команды.
Затем Linux core включает необратимый seccomp TSYNC. Динамическое ослабление фильтра
ради запуска сетевого процесса запрещено.

Дочерний процесс получает случайный ключ по наследуемой трубе, проверяется его PID
и образ на IPC. EOF трубы, завершение core или отмена неопределённого обмена
останавливают ребёнка. Повтор запроса не выполняется. Ошибка провайдера с корректным
аутентифицированным ответом сохраняет синхронизацию последовательности.

После успешного Lock/DestroyData демон передаёт Ack и завершает свою runtime-сессию.
UI при следующем открытии запускает новый демон; этот процесс снова создаёт idle
netd до фильтра. Так блокировка завершает и сетевые задачи. Локальный API остаётся
прокси и ждёт нового открытого пространства. CLI явно запускает `nymwrapd` перед
новой сессией.

## Ограничение

Наличие idle netd означает доступность компонента, а не одобрение исходящего
запроса или доказательство M2/M6. Политика профиля, окончательный leakcheck,
одобрение и долговременное резервирование бюджета проверяются отдельно.
