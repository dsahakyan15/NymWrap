# Настоящая локальная Tor-сеть и OS pcap

Unit-запись сериализатора не доказывает свойства пакетов. CI запускает Chutney
из официального torproject/chutney, commit
62b54a55215c94eb14adc22c5acd17b2ada04b76. Tor/tcpdump/tshark/nft — системные
инструменты Ubuntu runner; их версии записываются в артефакт. Chutney — только
тестовая зависимость, не часть поставки. Основание: [Tor research tools](https://research.torproject.org/tools/),
[проверка отказов Arti](https://arti.torproject.org/contributing/for-developers/testing/),
[закреплённый Chutney](https://github.com/torproject/chutney/tree/62b54a55215c94eb14adc22c5acd17b2ada04b76).

Временные client/relay netns имеют только veth с RFC 5737 адресами и не имеют
default route. Client разрешает nft только TCP к OR/Dir портам тестовой сети.
HTTPS-провайдер и авторитетный DNS — синтетические локальные процессы в relay
namespace; реальная сеть Tor, аккаунты и ключи провайдеров не используются.
Arti всё равно строит настоящие цепочки и проводит TCP через Tor.
Состояние Arti предварительно помещается в проверенный fscrypt-каталог.

Тест вызывает production Tor::send, общий TLS и HTTP код. Только cfg(test)
добавляет частные authorities, доверенный корень тестового PKI и key log для
расшифровки записи exit→HTTPS. В release этих полей и hooks нет. ClientHello
проверяется прежним golden отдельно. tcpdump пишет реальный pcap со стороны
client и провайдера; tshark восстанавливает HTTP. Независимый Node oracle требует
все 16 запросов, все пять корзин, совпадение SHA каждого тела с квитанцией
провайдера, отсутствие исходных/кодированных канареек и их частей USER_PATH.
Пустая, неполная запись или выключенная расшифровка не могут пройти.

Два conversation клиента должны иметь разные circuit IDs. После остановки
тестовых Tor-релеев отправка обязана отказать при живом HTTPS-провайдере.
Весь client pcap проверяется на отсутствие DNS и пакетов к provider:443 или
другим адресам/портам. Отдельная попытка прямого соединения должна отказать.
Положительные проверки oracle намеренно добавляют утечку, неверную длину,
пустую запись и прямой пакет. Регрессия Base64 полного пути — ADR 0063.

Namespace создаёт тестовый coordinator, а не production launcher. Поэтому даже
зелёный pcap не закрывает production namespace интеграцию M2/M6 или полный
Core/модель путь. Ограничения явно присутствуют в report.json. Тестовые pcap,
TLS session keys и публичный CA сохраняются для воспроизведения; приватные ключи
CA/провайдера не публикуются. Teardown завершает только процессы созданных netns,
останавливает захват, снимает mount и удаляет проверенный временный каталог.
