# Одноразовое исполнение поиска легенды

## Решение

Assisted остаётся режимом по умолчанию. В настройках можно явно выбрать
исполнение поиска расширением. Каждое действие запускается отдельной кнопкой
popup и запрашивает optional host permission своего сервиса. Поддержаны только
Google/YouTube search и текст до 512 Unicode scalar values. Видео, длинные
действия и веб-чаты ИИ остаются ручными, включая конфигурации с AI opt-in.

Перед первым действием браузера ядро выдаёт одноразовый permit только для точного
одобренного DriftTask текущего дня, плана и сервиса. Последний leakcheck при
daily_tasks повторно проверяет действующий список секретов: одобрение плана
до изменения секретов не разрешает экспорт теперь запрещённого текста.
Attempt записывается зашифрованным в CoverLog до выдачи permit. Его ключ включает
полный task; незавершённые записи не удаляются и не дают повторить этот task,
в том числе после рестарта. Одновременно допускается одна ещё не завершённая
попытка текущих задач; её блокировка других действий истекает через 15 минут.
Сам task остаётся заблокированным для нового автоматического исполнения.

Permit связан со случайной сессией workspace. Open, смена настроек/секретов или
shred инвалидируют старую сессию; реальные секреты и их хеши в CoverLog не
передаются. ValidateSearch проверяет permit, паузу, TTL, текущий день, точный
текст, одобрение и финальный leakcheck перед каждым шагом. Завершение также
проверяется ядром, включая минимальное время ввода/чтения с точностью до секунды.
Потерянный ответ не даёт права повторить действие. Nonce сессии и Rust-обёртки
permits очищаются через zeroize при освобождении.

## Поведение расширения

Фоновый процесс держит только один run в памяти. Он открывает отдельную видимую
вкладку на фиксированной главной сервиса, проверяет пустое поле и набирает текст
фиксированной функцией в isolated world. Задержки 60–180 мс на Unicode-символ;
затем открываются результаты по детерминированному allowlist URL. Ни ссылки,
ни form actions страницы не исполняются. Текст task передаётся только как данные,
без eval/Function/innerHTML. События ввода синтетические, fingerprint и isTrusted
не подделываются. Если сайт их не принимает, действие останавливается.

На результатах — 20–90 секунд ожидания с проверками политики/страницы раз в
секунду, затем FinishSearch. Общий watchdog — пять минут. CAPTCHA/login,
неизвестный redirect, невидимая/закрытая вкладка, изменённое поле, пауза, отмена,
отзыв разрешения или потеря core прекращают run. После возможного side effect
расширение пытается поставить Drift на паузу. CAPTCHA/login передают только
SafetyStop id/reason. Обхода проверок нет. Вкладка остаётся человеку для проверки.

Текст задач, permits и состояние run в browser storage не записываются.
При прерывании пользователь проверяет вкладку и может явно отметить действие
вручную. Новый worker не восстанавливает и не повторяет run. Повторная проверка
перед шагом не может отозвать байты уже начавшегося шага.

## Проверки и границы

Core-тест покрывает approvals, точный task, одноразовость, concurrent permit,
TTL/rollback, минимальное время, pause, смену секретов и reopen. Тесты расширения
исполняют run с управляемым временем, проверяют ритм, URL, повторы проверок,
cancel/revocation/CAPTCHA/login, изменённое поле и отсутствие replay. Канарейка
модельного плана в tests/leak блокируется до выдачи действий; лишние shadow-поля
не представимы в новых cover-командах. Новых зависимостей нет.

Настоящие Chrome/Firefox и изменяющиеся DOM сервисов требуют отдельной живой
проверки. Код не объявляет чтение результатов просмотром видео или исполнением
чата. Документация browser API: [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting),
[optional permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions).
