# Идентичность IPC на macOS и приватные тестовые каталоги

Первый реальный CI обнаружил две причины отказа IPC на Unix. Фикстуры создавали
сокет прямо в tempfile-каталоге с зависящими от umask правами; Listener правильно
отклонял 0755. Фикстуры теперь используют отдельный создаваемый 0700 подкаталог.
Listener создаёт недостающую иерархию с 0700, включая первый запуск без XDG runtime,
и по-прежнему отклоняет существующий публичный каталог, не меняя его права.

На Darwin interprocess 2.4.9 возвращает uid/gid через xucred, а PID в этом
представлении отсутствует. Вместо ослабления проверки PID читается из самого
соединённого сокета getsockopt(SOL_LOCAL, LOCAL_PEERPID) в nw-platform::sys.
Отказ, неправильный размер или неположительный PID запрещают аутентификацию.
Проверки uid и образа процесса сохранены. API подтверждены исходниками
[Apple XNU](https://github.com/apple-oss-distributions/xnu) и закреплённого libc.

Регрессии tests/leak/src/ipc_identity.rs проверяют приватную иерархию, отказ
публичному каталогу, точный PID/образ на обоих концах до канареечного обмена и
отказ обычному файлу на macOS. Linux/macOS результаты засчитываются только по
зелёному CI, а не по успешной сборке Windows.
