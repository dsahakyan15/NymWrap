# Локальная NER с проверяемыми буквальными фрагментами

## Решение

Перед удалённым canonicalize локальная модель получает уже детерминированно
минимизированный текст в quoted_data и возвращает только строгий JSON:
local_only и до 64 entities с типом и буквальным фрагментом источника. У неё
нет vault, инструментов, сетевого доступа или права задавать replacement text.

Код проверяет схему, размеры, вхождение каждого фрагмента, границы UTF-8,
отсутствие пересечения с плейсхолдерами и предел общего числа замен. Вхождения
заменяются кодом, значения попадают в mlocked vault. Вложенные фрагменты
обрабатываются с приоритетом длинного. Непридуманные здесь данные отсутствуют:
если фрагмента нет в источнике, вся операция блокируется.

Приватный worker принимает только именованную схему `privacy_v1`. Для неё
закреплённая GBNF в исходниках ограничивает генерацию: caller не передаёт
грамматику. Синтаксическое ограничение не заменяет проверки исходных фрагментов.
В llama-cpp-2 0.1.161 `sample()` уже вызывает accept; повторный accept удалён,
поскольку он нарушает состояние grammar sampler. Настоящий CPU-тест проверяет
валидный результат схемы на синтетическом запросе с плейсхолдером.

Модель может только усилить local_only. ADDRESS и IDENTIFIER всегда делают
разговор локальным независимо от её флага. Этот флаг сохраняется в зашифрованной
истории и не снимается продолжением. После canonicalize вновь проверяются все
канонические сообщения и исходящий transcript. Неудачная NER не вызывает
попытку удалённой отправки без неё. Локальные L0-запросы NER не требуют.

Старые ConversationRecord без force_local восстанавливаются с true: новую
гарантию нельзя задним числом приписать старому удалённому контексту. Для
удалённого продолжения пользователь начинает новый разговор.

## Границы и проверки

NER может пропускать сущности и излишне скрывать слова; её JSON и наличие
фрагмента не доказывают качество распознавания. Пользовательский список секретов,
детерминированные PII-шаблоны, просмотр и заключительный leakcheck остаются
обязательными независимыми мерами. Маленькая тестовая модель может вернуть
неверную схему; это безопасный отказ, а не повод отключать проверку.

Тесты проверяют буквальность, повторные вхождения, восстановление, усиление L0,
выдуманную сущность, подмену плейсхолдера и дополнительные поля-инструкции.
Новых зависимостей нет.
