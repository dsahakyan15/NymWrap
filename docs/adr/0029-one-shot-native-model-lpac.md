# Одноразовый LPAC для native GGUF и инференса на Windows

## Решение

Windows nw-llmd разделён на брокер приватного HTTP IPC и одноразовый синхронный
worker. Брокер открывает два GGUF только на чтение с read sharing, проверяет
SHA-256 и сохраняет handles, исключающие параллельную запись. Native parser
в брокере не вызывается. Перед открытием endpoint выполняется отдельный Probe:
оба GGUF должны действительно загрузиться в LPAC.

Каждый Complete/Embed запускает новый LPAC без capabilities. Наследуются только
stdio и две копии disk handles с FILE_GENERIC_READ. Модели не копируются на диск;
права на реальные файлы или родительские каталоги не меняются. Числа handles
передаются вместо внутренних меток аргументов. Worker дополнительно проверяет
AppContainer token, inheritance/disk type и создаёт собственные read-only копии.
Загрузка через FILE* из ADR 0028 проверяет SHA-256 до и после native parser.

Протокол — единственный bounded frame с version/shadow/request_id=1, строгими
типами и EOF. Произвольных grammar, путей, инструментов и имён моделей нет.
Лимиты сообщений совпадают с HTTP API, ответы повторно проверяются брокером.
Сырые кадры, тексты команд и ответов очищаются при Drop. Ошибка изоляции или
worker блокирует вызов; обходного запуска native backend в брокере нет.

Сохраняются private desktop, read-only fresh profile, HANDLE_LIST и атомарный
JOB_LIST: максимум один процесс, kill-on-close. Для модели лимит памяти 8 GiB,
времени 240 секунд; существующий importer остаётся на 512 MiB/120 секундах.
Worker не создаёт Tokio runtime: LPAC может запрещать сам WSAStartup. Внутри
native inference сохраняется прежний дедлайн 110 секунд.

## Последствия и проверки

Повторная загрузка и хеширование увеличивают задержку каждого вызова. Выбран
простой жизненный цикл без сохранения native контекста между запросами. Большая
модель, не укладывающаяся в job, завершается ошибкой. Новых зависимостей нет.

Реальные Windows tests проверяют read handle при запрете записи/открытия по пути,
запрет TCP/UDP/FS/spawn, отказ worker mode вне AppContainer и настоящий отдельный
бинарник через приватный IPC. CPU, NER с фиксированной грамматикой и embeddings
проверяются на закреплённых синтетических fixtures/GGUF. Протокол отвергает чужую
полосу/версию/id, лишние поля/кадры, превышение размера и некорректные векторы.

Это изоляция native worker, а не всех ролей M6. Брокер HTTP остаётся обычным
Windows-процессом и имеет handles исходных моделей. При штатном завершении
временный профиль удаляется. Аварийное завершение брокера закрывает job и убивает
worker, но может оставить профиль с публичной копией exe; данные запросов и
копии GGUF в профиль не записываются. Полная изоляция брокера/core/netd остаётся
отдельной работой.
