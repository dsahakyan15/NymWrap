# Mirror считает наблюдённые события и явные остановки

## Решение

Ранее поля decoys/challenges не обновлялись, а их нули делились на старые
счётчики. Отсутствие пути измерения выглядело как измеренный ноль. Добавляем
отдельные observation counters с serde defaults: старые пространства получают
неизвестные показатели до первых событий нового периода. Очистка Metrics
начинает новый период. Старые агрегаты активности/утечек сохраняются.

После успешного ответа nw-netd Route записывает либо подтверждённый decoy, либо
реальный удалённый запрос. L0, подготовка модели, зарезервированный бюджет,
ошибка транспорта и Uncertain в cover_ratio не входят. Событие сохраняется
до возврата ответа; сбой сохранения оставляет неопределённый исход без replay.
Метрика равна подтверждённым приманкам / подтверждённым удалённым запросам.

Расширение по-прежнему читает страницу только по кнопке и локально останавливает
снимок при CAPTCHA/входе. Отдельная явная кнопка отправляет SafetyStop с новым
случайным 128-bit event_id и reason=captcha/login. Адрес, заголовок, текст,
снимок, время страницы и задача в этом сообщении отсутствуют. Cover allowlist
отклоняет лишние поля, произвольный reason или неверный id.

Core сначала ставит Drift на паузу, затем учитывает остановку. Последние 64
event_id сохраняются в зашифрованном Metrics, чтобы повтор запроса после
потери ответа не увеличивал счётчик. Повтор всё равно подтверждает паузу.
Продолжение возможно только явной кнопкой пользователя. Challenge rate —
остановки / (остановки + выполненные действия легенды) нового периода.
Это добровольно учтённые события, а не наблюдение всей активности браузера.

Обновление counters сначала сохраняет новую копию, затем заменяет состояние
в памяти. При ошибке сохранения мутация в памяти не остаётся. Завершённый
workflow и Metrics лежат в разных доменах: сбой между их сохранениями может
недосчитать действие, но не повторяет его. Новых зависимостей нет.

## Проверки и интерфейс

Настоящее SQLCipher workspace проверяет миграцию старого counters, reopen,
дедупликацию stop, сохранение паузы, rates и очистку Metrics. Canary test
проверяет запрет содержания в SafetyStop. Тест с исполнением popup.js проверяет
локальный CAPTCHA capture, отдельное согласие, точные поля сообщения, отсутствие
содержания и блокировку повторного клика до ответа. Сам детектор и прочие
native bridge tests сохраняются. E2E проверяет stop через настоящий native host.

Desktop показывает оба показателя с определениями, прочерком для неизвестного
значения и явным обновлением из ядра, включая паузу, поставленную расширением.
Показатель не является захватом сетевого трафика и не закрывает критерии M3/M6.
