# Закреплённая проверка аудитов зависимостей

> Изменено [ADR 0111](0111-scoped-cargo-vet-exemptions.md) (2026-11-28): запрет exemptions заменён поштучным allowlist принятых рисков.

THREAT_MODEL §9 требует cargo-vet вместе с cargo-deny. Инструмент добавляется
как отдельный build/CI tool, без зависимости в приложении: cargo-vet 0.10.4,
официальный tag a9bde85910409be3d2d61e6f6ff6ba7a521f0412, MIT/Apache-2.0.
Архивы Linux/Windows и SHA-256 закреплены в workflow-tools.lock.json по metadata
официального [релиза](https://github.com/mozilla/cargo-vet/releases/tag/v0.10.4).
Перед запуском проверяются архив и извлечённый в память конкретный member;
другие пути архива не распаковываются. Нельзя подменить кешированную программу.
Actionlint использует тот же механизм; граница его проверки остаётся прежней.

У четырёх Cargo workspace отдельные stores: root, desktop, netd, fuzz. Это
позволяет сохранять imports.lock для каждого полного графа. В CI выполняется
check --locked; обновление импортов — отдельный явный локальный режим.
Публикуются JSON cargo-vet и receipt с кодом выхода и хешем инструмента.
Старая выдача удаляется перед новым запуском; ошибка/отсутствие JSON не зелёные.

Импортируются только опубликованные аудиты Mozilla и Google из immutable
commits 0ecbc0c0e1ffa71c171eca7e5f065adf35a46d08 и
640a51eb32e2f47d7ee8017a128485f7e1ce6780. Доверие ограничено явно записанными
аудитами и исходными criteria этих источников; чужие imports не наследуются,
criteria не ослабляются. Семантика — по [документации импортов](https://mozilla.github.io/cargo-vet/importing-audits.html).
Это доверие к их опубликованным проверкам, не аттестация отсутствия ошибок.

Автоматические exemptions, regenerate exemptions и фиктивные certify не
используются. [Обычный init](https://mozilla.github.io/cargo-vet/setup.html)
создаёт исключения для прежнего графа, поэтому его зелёный результат не является
приёмкой NymWrap. Непокрытые версии остаются явным провалом и задачей аудита.

Path forks не объявляются собственным проверенным кодом ради прохождения vet:
для совпадающего опубликованного пакета требуется audit-as-crates-io=true.
Согласно [правилам path dependencies](https://mozilla.github.io/cargo-vet/first-party-code.html),
это проверяет опубликованную базу, а не локальную разницу или вложенный native
код. Аудит локальных модификаций и C/ASM остаётся отдельным требованием M6.
Никаких собственных аудитов без просмотра исходников не заявляется. Новая
CI-проверка и M6 открыты, пока нет полных зелёных результатов и покрытия.
