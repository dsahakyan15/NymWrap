# Проверка декодированного содержимого Base64

PCAP-корпус воспроизвёл обход USER_PATH/2: minimize сохранял в vault только имя
пользователя, а модель возвращала Base64 полного /home/имя/project. Base64
отдельного имени не является подстрокой кодирования полного пути из-за границ
трёхбайтовых групп. Перечисления кодировок самого секрета недостаточно.

Финальный leakcheck проверяет дополнительно декодированное содержимое валидных
Base64 блоков: standard и URL-safe, с padding и без него. Проверяются обычный
вход и вариант без пробелов/переносов и перечисленных невидимых разделителей.
Два слоя декодирования ограничены 64 KiB результата на слой. Переполнение даёт
Block::TooLarge, без пропуска хвоста. Бинарная обёртка не скрывает UTF-8 секрет:
невалидные последовательности заменяются до прежней проверки известных значений
и детекторов. Проверка меток маршрута тоже использует декодированные значения.

Временные декодированные байты, строки, нормализованные значения и варианты
секретов принадлежат zeroize-объектам. Вывод модели не изменяется и не исполняется;
декодирование может только запретить отправку. Это конечный набор распознаваемых
форматов, а не распознавание произвольного скрытого кодирования.

Регрессии в tests/leak проверяют полный путь, разные выравнивания, бинарный
prefix/suffix, переносы, двойную Base64, метку с Device-секретом и GEO без
зарегистрированного секрета. Буквальная public-задача остаётся допустимой.
Матрица из девяти источников Device и семи детекторов во всех шести кодировках
сначала была красной на USER_PATH/2, после исправления прошла. OS pcap и
проверка настоящего Tor в отдельных namespaces этим unit-прогоном не заменены.
