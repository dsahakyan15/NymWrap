# 0003. Изолированная граница системных вызовов

Статус: принято. Дата: 2026-11-22.

Требования M1/M6 к SID/ACL, блокировке памяти и дампам требуют OS API. Вводится
маленький `nw-platform`; unsafe разрешён только в `src/sys.rs`, остальной
workspace сохраняет forbid(unsafe_code). Это не ослабляет инварианты: типы наружу
безопасны, сырые указатели не покидают модуль, ошибки приводят к отказу операции.
windows-sys 0.61.2 и libc 0.2.191 закреплены с lock-хешами.

Ключи находятся в secrecy и обнуляются zeroize до снятия блокировки страниц.
mlock/VirtualLock ведут общий счётчик ссылок на каждую страницу: уничтожение
одного маленького ключа не разблокирует соседний ключ на той же странице heap.
Linux страницы исключаются из core dump через MADV_DONTDUMP; Windows — из WER
через WerRegisterExcludedMemoryBlock. Демо-процессы отключают дампы RLIMIT_CORE /
PR_SET_DUMPABLE и heap/snapshot-отчёты WER. Ошибка блокировки не игнорируется.

Windows IPC использует явный SID TokenUser, а не OWNER RIGHTS: при повышенном
токене владельцем объекта по умолчанию может оказаться группа Administrators.
Клиент проверяет владельца kernel object перед передачей содержимого. Каталог
хранилища получает защищённый наследуемый DACL только для SID пользователя.
Администратор и захват уже разблокированной машины остаются вне модели угроз.

Сборка SQLCipher требует native Windows Perl для vendored OpenSSL. Скрипт
bootstrap-perl.ps1 загружает только build dependency в target/tools, проверяет
закреплённый SHA-256 из официального releases.json и извлекает perl/bin и perl/lib.
Системные настройки и PATH машины не меняются. Готовая программа Perl не требует.

В MSVC отключено только сообщение LNK4099 об отсутствующем upstream PDB в
статических архивах OpenSSL. Код ошибки, символы и проверки компоновки не
игнорируются. Это не влияет на шифрование и содержимое бинарников.
Windows VirtualLock ограничен минимальным working set процесса (обычно 50 страниц).
SQLCipher тоже блокирует свои выделения; после открытия нескольких доменов этого
недостаточно для vault. При первом отказе программа один раз запрашивает минимум
16 МиБ и мягкий максимум не менее 64 МиБ только для своего процесса, затем
повторяет VirtualLock. При отказе ОС операция завершается ошибкой; глобальные
лимиты, привилегии и настройки безопасности не меняются.
