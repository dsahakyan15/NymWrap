# Linkcheck по накопленным данным провайдера

Между canonicalize и финальным leakcheck добавляется детерминированное сравнение
с досье: подтверждённая персона, все личные и Device-секреты, сводка импорта.
Не меньше 50 различных синтетических досье не зависят от данных пользователя.
Векторизатор сообщает SHA-256 реально загруженного и проверенного файла модели;
старый endpoint без идентичности, другая модель, неверные векторы или превышение
лимита не разрешают удалённую отправку. Векторы и досье живут только в shadow
памяти с zeroize, исходные данные хранятся в прежних зашифрованных доменах.
В production Workspace проверяет образ процесса nw-llmd по ядру перед передачей
тела; чужой same-user endpoint не должен получать досье. Само поле SHA-256 в
ответе не является аттестацией произвольного процесса. Регрессия проверяет
отсутствие обращения к backend при неверном образе и успешный контроль.

Начальная версия использует уже закреплённый nomic-embed-text-v1.5 Q4_K_M,
SHA-256 d4e388894e09cf3816e8b0896d81d265b55e7a9fff9ab03fe8bf4ef5e11295ac,
mean pooling, 768 координат, одинаковый search_document prefix. Косинусы
квантуются с шагом 1e-6; равенство учитывается консервативно: возможное попадание
пользователя в top-k уже риск. Порог и k — настройки профиля. Эти начальные
значения ещё не прошли held-out приёмку. [Карточка модели](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5)
обозначает English; наличие UTF-8 входа не доказывает качество RU/HY.

Проверяется полная уже видимая провайдеру история плюс предлагаемый ход.
Generalize может менять новый ход, но не удаляет ранее переданные факты из
оценки. Модель не определяет безопасность своего переписывания: повторяются
linkcheck и затем leakcheck после последней генерации. Оставшийся риск требует
независимых разговоров с независимыми удостоверениями; новый ID при том же
L3-ключе независимостью не считается. Без такого транспорта/одобрений — L0 с
объяснением. Разбиение и его интеграция остаются открыты до реальной проверки.

Ранжирование, production-досье, generalize/recheck и переход в L0 подключены
к Engine и проверке независимых cover-приманок. Изменение персоны/подтверждений
или импорта инвалидирует старые разрешения и кеш. Новые локальные регрессии
проверяют весь Engine/shape путь, сохранение отправленного префикса, канарейку
после generalize и отсутствие обхода при ошибках. Этап остаётся открытым:
нужны split, 300+ EN/RU/HY, замороженные пороги и слепая held-out оценка со
статистикой полезности, отказов и утечек. Все-L0 не считается успешной защитой
удалённого пути. Сегментирование полного досье и пределы описаны в ADR 0061;
превышение пределов выбирает L0 без обрезания. Оценка качества остаётся открытой.

Причина L0 хранится и передаётся отдельным enum local_reason. Текст ответа
модели не получает префикса: иначе NymWrap ломает корректный JSON и другие
структурированные ответы. UI показывает объяснение рядом с уровнем доверия;
совместимый HTTP API добавляет nymwrap.local_reason/explanation в метаданные.
