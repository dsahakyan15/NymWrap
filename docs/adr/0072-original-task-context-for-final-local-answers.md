# Исходный контекст для окончательного локального ответа

При переходе в L0 Engine передавал финальной локальной модели ту же canonical
историю, которую готовил для удалённой отправки. Minimize, NER и generalize могут
убрать необходимые числа и условия задачи. Это безопасный отказ от отправки,
но не полезный локальный ответ. Маскированные значения не нужны локальной модели
на стадии переписывания; они могут быть необходимы для решения исходной задачи.

Финальный ответ L0 получает настоящую историю только текущего разговора:
проверенные тексты пользователя и ранее показанные ответы с исходными ролями.
Это не всё досье, не таблица vault и не список секретов устройства. Неупомянутые
секреты модели не добавляются. NER, canonicalize и generalize по-прежнему видят
только минимизированный текст. Модель работает без сети, инструментов и доступа
к vault через API или файловую систему; временные Message очищаются при Drop.
Сохранение происходит в прежних зашифрованных доменах shadow.

Перед финальной генерацией L0 разговор получает постоянный force_local. Это
касается и явно выбранного локального хода после уже отправленных удалённых
ходов. Исходный ответ L0 может содержать редкие факты и секреты; его нельзя
включать в следующую удалённую историю даже после смены маршрута или перезапуска.
Флаг сохраняется в encrypted snapshot и проверяется также перед созданием
удалённого одобрения. Ранее отправленные провайдеру факты остаются раскрытыми.
Для удалённой работы пользователь начинает отдельный новый разговор.

Новые snapshots имеют version 2. В version 1 нельзя отличить полностью
удалённую историю от remote → local с force_local=false, поэтому все старые
разговоры восстанавливаются только локально. История и таблица плейсхолдеров
сохраняются; неизвестная версия отвергается. Это консервативная миграция без
изменения шифрования или ключей. Отдельная отрицательная регрессия сначала
воспроизвела удалённое одобрение для такого старого encrypted snapshot.

Регрессии в tests/leak проверяют исходное число задачи при явном L0, отсутствии
досье и недоступном NER; отсутствие сырых значений в переписывании; отсутствие
неупомянутого Device-секрета в окончательной генерации. Сценарий remote → local
→ remote проверяет исходные роли/ответ провайдера, отсутствие повторной отправки
и одобрения после encrypted reopen и отсутствие канареек в файлах данных.
Это исправление сохранения контекста, не измерение качества настоящей модели и
не замена открытой development/held-out приёмки linkcheck.
