# Подпись выпуска ключом Tauri signer

THREAT_MODEL A7 требует подписанные выпуски. Сертификаты Authenticode и Apple
Developer платные, поэтому выпуск подписывается ключом `tauri signer`. Это
формат minisign (Ed25519, предхеш BLAKE2b-512), который модель угроз уже
называла. CLI `@tauri-apps/cli` уже закреплён в `app/`, новых зависимостей нет.

Порядок:

- `node scripts/release-signature.mjs keygen` создаёт ключ под паролем вне
  репозитория (`~/.nymwrap-release/`) и закрепляет открытый ключ в
  `release/nymwrap-release.pub`;
- `sign <dir>` записывает `SHA256SUMS` всех файлов выпуска (плоский каталог,
  без ссылок) и подписывает его. Пароль вводится скрыто: `tauri signer sign`
  сам не спрашивает пароль и молча пробует пустой;
- `verify <dir>` проверяет подпись и trusted comment, затем каждый хеш. Лишний,
  отсутствующий или изменённый файл отвергает весь выпуск.

Проверка написана на `node:crypto` независимо от подписывающего кода. Тест
подписывает настоящим Tauri CLI и проверяет совместимость, подмену файла,
подпись чужим ключом и правку trusted comment.

Подписание выполняется только на машине владельца ключа. Ключ не кладётся в
секреты Actions: публичный репозиторий (ADR 0079) и CI не должны иметь права
выпускать от имени владельца. Порядок выпуска: CI собирает артефакты, владелец
собирает их повторно, сравнивает хеши (воспроизводимость, M6) и только тогда
подписывает.

Плагин автообновления Tauri не подключается: он дал бы сеть процессу UI в
обход `nw-netd` (инвариант 2).

Ограничения, которые видит пользователь: подпись доказывает происхождение и
целостность, но Windows SmartScreen и macOS Gatekeeper продолжают показывать
«неизвестный издатель». Для этого нужны платные Authenticode или Azure Trusted
Signing и нотаризация Apple; они вне рамок проекта.
