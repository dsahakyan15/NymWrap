# Асинхронные задания через приватный HTTP API

## Решение

POST /v1/nymwrap/chat/jobs использует обычную строгую схему chat completions,
но только модель nw/remote/default. Подготовка идёт через тот же Engine.review,
последний leakcheck и замороженную capability; затем обычный StartRemoteJob.
Обязательный просмотр блокирует автоматическое принятие capability. До создания
задания проверяются min-trust и epoch; смена конфигурации заменяет Engine и
делает старую capability непригодной. Чувствительный ввод получает локальный
ответ 200 без задания. Очередь возвращает 202 и id для опроса.

GET /v1/nymwrap/jobs/{id} открывает только конкретное задание, DELETE отменяет
его с прежней семантикой Uncertain после Sending. Список заданий и исходные
сообщения не добавляются в HTTP API. Host/origin/lane, приватный IPC, лимиты,
no-store и запрет автоматического retry те же, что у синхронного endpoint.
В HTTP не добавлены сетевой listener, прямой транспорт или повтор send.

## Проверки и границы

Канареечный тест в tests/leak проходит HTTP-десериализацию, настоящий Engine,
review/approve и shaping; инъекция после модели блокирует выход. Сквозной тест
проверяет настоящий core, CPU-модель, mandatory review, min-trust, Constant,
опрос, отмену и L0. Клиентский idempotency key пока отсутствует: потеря ответа
POST не даёт права на автоматическое повторное создание.

В тестовом crate добавлены только уже закреплённые workspace-зависимости
nw-api/axum/tower/http-body-util для проверки HTTP-границы. Новых внешних пакетов
или версий нет, Cargo.lock обновлён.
