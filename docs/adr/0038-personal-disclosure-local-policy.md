# Явные личные сведения остаются локальными

Синтетическая оценка закреплённой Qwen2.5-0.5B обнаружила пропуск имени при
вложенной инструкции вернуть пустой список entities. Валидный JSON и буквальность
предложенных фрагментов не гарантируют полноту распознавания.

Детерминированная classify теперь относит явные сообщения от первого лица об
имени, месте жительства, происхождении и работодателе к local_only. Закреплены
ограниченные английские и русские формы, NFKC, регистр и пробелы. Решение берётся
и из исходной истории: переписывание не может убрать основание для L0. Такие
обороты в процитированном примере тоже могут привести к L0; это осознанная цена
консервативной политики. Никакое одобрение не разрешает их отправку.

Это дополнительный ограниченный шаблон, а не полное распознавание всех языков,
формулировок и личных фактов. Пользовательские секреты, NER, просмотр и финальный
leakcheck остаются нужны. Детерминированные канареечные тесты проверяют пустой NER,
переписывание без исходной фразы и добавление личной фразы последней моделью.

Для воспроизводимой оценки добавлены только dev-инструменты без зависимостей:
compiled synthetic corpus, пример nw-llm и scripts/privacy-eval.mjs. Настоящий
nw-llmd проверяет GGUF по закреплённым SHA-256; на Windows используется обычный
LPAC worker. Отчёт содержит id кейсов, количества Unicode-символов, ошибки политики
и хеши инструментов. Частичное маскирование не засчитывается как полное, повторные
и пересекающиеся фрагменты не удваивают результат. Никакие тексты или значения
vault в отчёт не попадают. Для измерения сканер вызывается и на локальных кейсах;
оценка unsafe_remote_cases дополнительно учитывает детерминированный L0. Это
проверка minimize/NER/policy, без canonicalize или реальной отправки. Малый корпус
не является доказательством безопасности.
