# 0004. Встраиваемый llama.cpp в отдельном процессе

Статус: принято в рамках реализации выбранного в SPEC движка llama.cpp.

`nw-llmd` встраивает CPU-движок через закреплённый `llama-cpp-2 = 0.1.161`.
Он открывает только приватный IPC, принимает два ограниченных типизированных
запроса (chat и embeddings), не имеет HTTP-клиента, загрузчика моделей или
инструментов. Модели задаются локальными путями и обязательными SHA-256.
Проверка выполняется до вызова парсера GGUF. Отображение изменяемого файла в
память отключено. Модель диалога должна содержать поддерживаемый chat template.

Все операции исполняются последовательно: контексты одной модели не создаются
параллельно. Каждый запрос получает новый контекст, фиксированный greedy sampler,
лимиты входа, вывода и времени. Логи llama.cpp отключены, ошибки содержат коды.
Сетевой запрет ОС применяется отдельным nw-sandbox; отсутствие HTTP-клиента само
по себе не считается проверенной песочницей.

CPU выбран как переносимая базовая сборка без динамической загрузки GPU-плагинов.
Новая зависимость нужна для поддержки named pipes на Windows без TCP-прокси и
внешнего процесса, который мог бы открыть сеть. Код урока не импортируется.

Сборка требует CMake, C++ и libclang. Windows bootstrap закрепляет libclang 18.1.1
из PyPI (обёртка LLVM, SHA-256 в scripts/bootstrap-libclang.ps1), извлекая только
DLL и лицензию в target/tools. Это инструмент сборки, не компонент релиза.
Источники: https://github.com/utilityai/llama-cpp-rs и
https://github.com/sighingnow/libclang. Версии и контрольные суммы Rust-зависимостей
фиксирует Cargo.lock; cargo-deny обязателен.
