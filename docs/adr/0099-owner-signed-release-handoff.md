# Передача воспроизводимого выпуска владельцу ключа

Статус: принято. Дополняет ADR 0080 и 0098; зависимостей не добавляет.

`release.yml` запускается только вручную (`workflow_dispatch` с выбранным
существующим version tag) или при push `v*`. Проверка ref требует тег
`vMAJOR.MINOR.PATCH` с необязательным prerelease. Обычный push ветки/PR
проверяет воспроизводимость, но не создаёт Release. Теги создаёт владелец.

Release workflow вызывает тот же `reproducible.yml`, а после успешного
сравнения и проверки SBOM выкладывает неподписанный набор в **draft** GitHub
Release. Права `contents: write` получает только последний job; сборщикам
доступен лишь read-only токен, checkout не сохраняет credentials. Секретов
подписи, пароля, signing action или keygen в workflow нет. Повторный запуск
не перезаписывает существующий Release: `gh release create` завершится ошибкой.

Владелец скачивает все пять файлов из draft/Actions, проверяет commit в
buildinfo, делает чистую локальную сборку ровно этого commit, запускает
сравнение всего набора. Только затем существующий `release-signature.mjs sign`
пересоздаёт SHA256SUMS и подписывает его локальным ключом вне репозитория.
Проверяются также SBOM, buildinfo и файлы расширения внутри архива. Владелец
загружает SHA256SUMS и SHA256SUMS.sig и публикует draft после `verify`.
Пошаговые команды приведены в USER_GUIDE, раздел «Проверка скачанного выпуска».

Неподписанные Actions artifacts и draft не предназначены для установки;
GitHub автоматически добавляемые source zip/tarball не являются частью
подписанного плоского набора. Ключ `release/nymwrap-release.pub` уже закреплён,
создавать новый keygen для каждого выпуска нельзя. Ключ и пароль остаются
только у владельца, не в Actions secrets, репозитории, build container или
артефакте. Подпись не доказывает аудит кода и не делает cargo-vet зелёным.
Автообновления Tauri не подключаются; сетевые инварианты приложения сохраняются.
