# Удалённый конвейер и одноразовый просмотр запроса

## Решение

Доступный удалённый маршрут — Tor с пулом ключей провайдера, уровень L3.
Strict/paranoid требуют более сильный маршрут и отклоняют L3. Чувствительный
запрос остаётся L0. Ошибка удалённого запроса не вызывает локальную или прямую
повторную отправку. Отпечаток NetConfig закрепляется за разговором и живым netd;
изменение провайдера требует новой сессии и нового разговора.

Core проверяет наличие ключа и дневной бюджет до bootstrap. Непосредственно перед
send он сохраняет аренду ключа и резерв верхней оценки стоимости в зашифрованном
Vault. Лимит сейчас применяется ко всем попыткам, включая реальные запросы: это
консервативное ограничение расходов до разделения бюджета очереди и приманок.
Резерв сохраняется при неопределённом результате, смене суток и очистке Metrics.
Изменение сессии отменяет операцию; отменённый обмен убивает дочерний netd.

Просмотр замораживает ConversationVault, каноническую историю и Prepared после
последнего этапа модели. Случайный 256-битный approval_id и SHA-256 связывают
содержимое, разговор, NetConfig и max_tokens. До 16 просмотров живут только в
памяти, срок — 300 секунд по монотонным часам. Изменять разговор с ожидающим
просмотром нельзя. Другие разговоры доступны. Подтверждение потребляет capability
перед проверкой и send; ошибочный hash, отмена и ошибка транспорта не позволяют
повторить отправку тем же одобрением. Перед send leakcheck выполняется снова,
модель повторно не вызывается. Изменение конфигурации заменяет Engine и аннулирует
его просмотры. GUI показывает данные только через textContent и предлагает
отдельную кнопку отправки. API без человеческого просмотра возвращает
approval_required, если профиль требует его.

API помечает ошибки `x-should-retry: false` и использует 424 для терминальной
ошибки маршрута. Это дополнительный сигнал клиентам, а не гарантия поведения
любой внешней программы. Официальный [Python SDK](https://github.com/openai/openai-python/blob/main/src/openai/_base_client.py)
проверяет этот заголовок в `_should_retry`.

## Проверки и границы

Тесты выхода сравнивают сообщения с просмотренным transcript, проверяют канарейку,
один вызов модели, повторное одобрение, отмену, подмену hash и провайдера. Для
декодирования исходящего JSON тесты используют уже закреплённый serde_json
workspace; новая runtime-зависимость не добавляется.

Сквозной Windows-тест проверяет настоящую Tor/TLS-ошибку с синтетическим ключом,
затем аварийно завершает собственный core после сохранения резерва. После запуска
резерв остаётся, повторов нет. Это не проверка успешного платного провайдера,
полной анонимности, постоянного cover-трафика или всех песочниц M6.
