# Ожидание модели и сети без общей блокировки разговоров

## Решение

Подготовка читает неизменяемую подтверждённую историю и строит отдельный turn.
До выполнения completion берётся краткая резервация conversation id; общая
блокировка BTreeMap освобождается. Независимый L0-разговор доступен, пока другой
запрос ждёт Tor или провайдера. Конкурентное изменение/восстановление того же
разговора возвращает request_in_progress. Одобренный просмотр использует ту же
резервацию. Подтверждённая история обновляется только готовым проверенным ответом.

Резервация снимается RAII даже при отмене future. Forget посылает отмену, убирает
историю/просмотры, а biased select прекращает ожидающий completion; ответ уже
забытого turn не может воскресить историю. Изменение workspace дополнительно
останавливает Route через существующий epoch watcher. Занятие и очистка map
используют короткий std::sync::Mutex без await, токен отмены — watch<bool>.

## Проверки

Регрессионный тест воспроизвёл прежнюю блокировку: завершение локального чата
истекало через 500 мс, пока тестовый remote ждал отдельного сигнала. После
изменения L0 отвечает до сигнала remote. Проверены также конфликт одного id,
forget во время ожидания, abort задачи, снятие резервации и отсутствие записи
незавершённого turn. Новых зависимостей нет.
