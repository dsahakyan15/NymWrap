# Общий dispatcher nw-netd и срок ожидания авторизации

Существующий OS pcap вызывает Tor::send прямо из тестового процесса. Это
проверка транспорта, но не доказательство production IPC и разделения core/netd.
Для сквозного сценария сервер AEAD IPC вынесен из main в один модуль server,
который использует и настоящий демон. Последовательности сообщений,
Initialize/Reset/Send/SendOnce и отсутствие replay сохранены.

Публичный serve всегда выбирает production Tor constructor. Смена фабрики
доступна только внутри crate; частный CA/Chutney останутся cfg(test), без
runtime флага или команды wire в release. Это позволяет подключить частную Tor
сеть в другом процессе с настоящим dispatcher. Само выделение модуля ещё не
добавляет такую процессную интеграцию и не меняет scope прежнего pcap отчёта.

Native регрессия воспроизвела задержку: один same-user peer подключается и не
пишет frame; следующий разрешённый Reset не проходит за 4 секунды, потому что
общий read_frame ожидал до 120 секунд. До проверки AEAD теперь действует срок
2 секунды. Просроченная/неверная запись не расходует sequence, не вызывает
конструктор транспорта и не получает ответ с содержанием. Это предел одного
пустого соединения, не заявление о защите от потока DoS-соединений.

Проверяются native lifecycle и канареечный путь через этот dispatcher:
неправильный ключ/старый sequence не вызывают транспорт; легальный Send и
SendOnce передают только подготовленное тело, ответы защищены тем же AEAD,
Reset отзывает соединение. Все фабрики-заглушки существуют только в тестах.
Реальный процессный pcap и production namespace интеграция остаются открытыми.
