# NymWrap: работа с личным пространством

NymWrap разделяет реальные вопросы (Shield) и действия выбранной легенды (Drift).
Purge помогает выбрать старые следы для удаления, Mirror измеряет изменения.
Диалог доступен через локальную модель L0 и Tor с ключом провайдера L3 в standard.
При включённой защите устройства удалённая отправка требует полной проверки
секретов устройства моложе суток; её состояние видно на странице «Гигиена».
Strict/paranoid запрещают имеющийся L3. Метрики не обещают
анонимность и не доказывают, что сервис забыл данные обучения.

Явные личные сведения вида «меня зовут», «я живу», «я работаю», `my name is`,
`I live in`, `I work at` остаются только в локальной модели, даже если NER
вернул пустой список или переписывание убрало вводные слова. Цитата с такой
фразой тоже может остаться локальной. Список формулировок ограничен: заносите
важные значения в секреты и проверяйте показанный текст перед отправкой.

Медицинские и финансовые темы с известными системе маркерами также остаются
локальными независимо от ответа NER. Это консервативная политика: общий вопрос
о здоровье может получить L0. Список маркеров на английском, русском и армянском
ограничен и не заменяет проверку содержания.

Если после обычных масок и NER осталась похожая на имя последовательность из
двух слов с заглавными буквами, запрос остаётся L0. Дефисы, апострофы и NFKC
учитываются. Такое решение сохраняется, даже если переписывание потом убрало
имя. Проверяются и новые имена после переписывания. Публичное собственное
название тоже может получить L0; одиночные и написанные строчными буквами имена
этот ограниченный шаблон не гарантирует обнаружить. Объявленный секрет или
полностью распознанная NER сущность заранее закрываются плейсхолдером и сами
по себе этот дополнительный запрет не вызывают.
Исключение — исходная строка с признаком имени, которую меняет NFKC:
она консервативно остаётся L0 без сопоставления несовместимых смещений символов.

## Сборка

Нужны Rust из rust-toolchain.toml, Node.js, CMake и C++ toolchain. Для Windows
нужны Visual Studio Build Tools с Windows SDK и WebView2. Вендорная сборка
SQLCipher использует OpenSSL и нативный Perl. llama.cpp требует libclang.

В PowerShell из корня проекта:

```powershell
./scripts/bootstrap-perl.ps1
./scripts/bootstrap-libclang.ps1
. ./scripts/build-env.ps1
cargo build --workspace --locked
cd app
npm ci
npm run desktop
```

Bootstrap проверяет закреплённые SHA-256 и извлекает средства сборки только в
target/tools. Системные настройки не меняются. На Linux установите CMake, Clang,
libclang, pkg-config, OpenSSL headers, D-Bus headers и Secret Service. На macOS
нужны Xcode Command Line Tools и разблокированный Keychain.

Полный `scripts/check.ps1` требует PowerShell 7 (`pwsh`); проверка SBOM использует
его JSON Schema API. Базовые команды сборки выше работают и в Windows PowerShell
5.1. В Git Bash доступен `scripts/check.sh`; Windows AppContainer tests и проверку
SBOM в этом случае запускайте отдельно.

## Создание и блокировка

На странице «Обзор» создайте пространство. Standard позволяет пустой пароль;
Strict требует не менее 12 байт. Ключ дополнительно зависит от секрета в
хранилище ключей вашей ОС. Потеря пароля или этого секрета означает потерю доступа.

## Гигиена и секреты устройства

После открытия пространства отдельный worker читает идентификаторы устройства,
домашние пути, часовой пояс и глобальную git-личность. Повтор — раз в сутки или
кнопкой «Повторить проверку устройства». Результат хранится зашифрованным;
значения добавляются в секреты Shield с видом Device. Удалённые вами значения
не возвращаются при следующем автоматическом сборе. Настройки ОС не меняются.

Недоступный источник показан явно. Пока хотя бы один обязательный источник не
проверен, при включённой защите устройства отправка через Tor остановлена.
Локальная модель работает. На текущей Windows user display/Wi-Fi могут остаться
недоступными даже в отдельном AppContainer; дополнительных разрешений программа
ради этого не получает. Ручное добавление секретов не выдаётся за успешную
автоматическую проверку источника.

Экран «Гигиена» показывает наблюдения настроек отдельно от ручных инструкций.
Поддержаны чтение MAC-рандомизации из доступных Wi-Fi профилей, осторожная
проверка имени компьютера и явные Windows-политики геолокации/LLMNR. Отсутствие
политики или доступа означает «не измерено». NetBIOS, mDNS, часы, браузер и
остальные источники ОС ещё требуют реализации. NymWrap не меняет настройки.

Оценка hygiene_score — число подтверждённых пунктов из шести; неизвестные пункты
не исключаются из знаменателя. Рядом показано, сколько пунктов измерено. Нет
наблюдений, снимок старше суток или время из будущего — оценка неизвестна.
Снимок хранится зашифрованным. Чтение профилей не подтверждает отсутствие пакетов
в сети; инструкции ручной проверки не повышают оценку.

Shield скрывает форматы координат, MAC, IMEI с корректной контрольной суммой,
домашние имена в путях, часовые пояса, точные метки времени и GUID. В пути
сохраняется имя проекта. Для даты с явным смещением плейсхолдер содержит час UTC,
например `⟨NW_DATETIME_1_20261123T0800Z⟩`; исходное значение возвращается при
rehydrate. Это распознавание форматов: косвенное описание места может сохраниться.

Вложения обоих chat API получают HTTP 415 с кодом `attachments_not_supported`.
Файл и его метаданные не передаются модели или провайдеру. Поддерживается только
строковый текст; мультимодальные массивы content также отклоняются.

Windows может показать напоминание EFS о резервной копии ключа при первом
шифровании служебных файлов. Для тестовых запусков можно выбрать «Отложить
архивацию». Экспорт ключа пользователь выполняет сам; NymWrap не нажимает
системные диалоги и не отключает напоминание в настройках Windows.

### Отложенные задания API

`POST /v1/nymwrap/chat/jobs` принимает `X-NymWrap-Defer: 2`: готовое задание
получает случайное время допуска к отправке в пределах двух часов. Допустимы
целые 0–168 часов; 0 отменяет задержку по умолчанию. В других эндпоинтах и при
дублирующемся заголовке запрос отвергается. Заголовок наружу не передаётся.

Поле ответа `not_before` — локальное время допуска в Unix seconds. Очередь,
слоты, бюджет и доступность транспорта могут задержать отправку дальше. До
этого времени расходы не резервируются и отправка запрещена. Во время ожидания
можно отменить задание. Перезапуск не повторяет ранее одобренную отправку.

Окно входит в Idempotency-Key: тот же ключ с другим окном даёт конфликт.
Прежние квитанции без заголовка совместимы. Режимы с обязательным одобрением
сохраняют его: API не разрешает обойти просмотр заголовком Defer. Для заданий,
одобренных в UI, берётся `hard.defer_max_hours` конфигурации (paranoid: 2 часа).

### Границы сеанса

После открытия пространства первый внешний запрос ждёт случайные 5–30 минут.
Это относится и к приманкам. Локальные ответы доступны сразу; внешний синхронный
вызов во время ожидания получает `async_remote_required`. Время `not_before`
задания учитывает также начальную задержку; нулевой Defer её не отменяет.
Оставшееся время показано в настройках ритма и обновляется кнопкой состояния.
Перевод системных часов вперёд не разрешает ранний первый запрос.

Отдельный флажок разрешает после закрытия окна ещё 10–60 минут держать core,
локальную модель и ключи в памяти для независимых платных приманок. По умолчанию
он выключен; нужны также согласие на автоматические приманки, standard/Tor L3
и готовая защита устройства. Действуют обычные бюджеты и отдельные ключи.
Недоступность маршрута, ключей или бюджета останавливает отправку. Strict/paranoid
пока завершают сеанс без хвоста. Сон и выключение компьютера могут его оборвать.

При закрытии реальные задания отменяются; уже начатая отправка получает
неопределённый результат без повтора. Доступ к данным снова требует пароля.
Повторное закрытие не продлевает выбранный хвост. Кнопка «Заблокировать» сразу
завершает и приманки, и удержание ключей. Под L3 провайдер по-прежнему видит
суточный ритм запросов одного ключа — временные задержки не убирают эту связь.

### Мосты Tor

В настройках выберите obfs4, Snowflake или WebTunnel и вставьте до 16 строк мостов
одного типа. Сохранённые строки повторно не показываются; статус содержит тип
и число строк. Для изменения вставьте строки заново, для отключения выберите
«Без мостов». После изменения заблокируйте и снова откройте пространство и
начните новый разговор. Параметры хранятся зашифрованными и защищаются Shield.

Сборка устанавливает закреплённый Lyrebird автоматически; отдельно для debug:
`node scripts/fetch-transports.mjs`. Runtime не скачивает транспорт и не ищет
команды в PATH. Отсутствующий или изменённый бинарник и неработающий мост
останавливают выход; перехода на прямой Tor нет. Полный bridge bootstrap и
проверка изоляции ещё не подтверждены CI, поэтому этап остаётся открытым.
Мост видит IP машины. Он помогает скрыть обычное подключение Tor от оператора
сети и не повышает L3 до L1/L2. В paranoid мост рекомендуется, но имеющийся L3
этим не разрешается.

### Время активности легенды

При построении нового плана задайте начальный и целевой час UTC и длительность
окна. Исходный вариант — 12:00–18:00 UTC без сдвига; это не оценка вашей активности
по импорту. Для каждого этапа будет показано его окно. Начало сдвигается не больше
чем на два часа за этап; окно может переходить через полночь. Часовой пояс, IP и
геолокация браузера остаются его настоящими настройками.

Расписание входит в одобрение плана. Вне окна core не выдаёт задачи и останавливает
исполнение уже выданного search permit. Автоматического наверстывания пропущенных
действий нет. Прежние планы без окна продолжают действовать с прежним хешем;
для получения расписания постройте и одобрите новый план.

## Хранение

Зашифрованные базы находятся в LOCALAPPDATA/NymWrap/store на Windows и
XDG_DATA_HOME/nymwrap/store (обычно ~/.local/share/nymwrap/store) на Unix.
Единственный владелец хранилища — `nymwrapd`. UI, CLI и API обращаются к нему по
закрытому IPC. UI запускает его автоматически. При блокировке или нормальном
закрытии окна демон завершает сессию и свой сетевой дочерний процесс.

«Заблокировать пространство» закрывает хранилище и убирает показанное содержание
из окна. Для продолжения откройте пространство снова. Сводка, подтверждённая
персона, одобрения и прогресс сохраняются зашифрованными между запусками.
SQLCipher шифрует базы; записи дополнительно защищены XChaCha20-Poly1305.
Доменам истории, vault, персоны, легенды, импорта и метрик назначены разные ключи.

Историю Shield можно открыть из списка разговоров. После перезапуска сохранённый
контекст и соответствия плейсхолдеров восстанавливаются при продолжении. Если vault
разговора уничтожен, история доступна только для чтения.

Настройки позволяют сохранить API-ключи в отдельном сервисе хранилища ОС. Значения
не возвращаются в интерфейс. Для удалённого диалога отдельно настройте маршрут
Tor, HTTPS-хост и путь провайдера, имя модели и верхнюю оценку стоимости. Ключ из
пула даёт только L3. Удаление ключа здесь
не отзывает его у провайдера. Уничтожение vault/пространства удаляет OS-записи.

## Локальная модель

`nw-llmd` работает с локальными GGUF. Он ничего не загружает самостоятельно.
Перед запуском получите модель диалога с chat template и nomic-embed-text для
эмбеддингов. В настройках укажите полные пути и проверенные SHA-256 обоих GGUF,
затем нажмите «Запустить проверенные модели». Загрузка может занять до двух минут.
Они завершатся при блокировке пространства; для продолжения запустите их снова.
Имена для встроенного worker — `default` и `nomic-embed-text`.

На Windows загрузка GGUF и каждый вызов модели выполняются в новом AppContainer
без сети, записи и доступа к пользовательским каталогам. Передаются только
дескрипторы двух моделей на чтение; копий GGUF не создаётся. Повторная загрузка
увеличивает задержку. Лимит worker — 8 GiB памяти и четыре минуты на весь вызов;
если изоляция или загрузка не сработали, запрос завершается ошибкой.

Альтернатива — отдельно запущенный приватный сервер:

```text
nw-llmd --socket PRIVATE_ENDPOINT --model ABSOLUTE_CHAT_GGUF --sha256 HASH --embed-model ABSOLUTE_EMBED_GGUF --embed-sha256 HASH
```

PRIVATE_ENDPOINT скопируйте из настроек приложения. На Windows это named pipe
с именем nymwrap и идентификатором пользователя; на Unix — путь приватного
сокета. TCP-прокси для модели не нужен. Сервер обслуживает имена `default` и
`nomic-embed-text`. На Windows и macOS клиент дополнительно проверяет, что
приватный endpoint принадлежит бинарнику `nw-llmd` из поставки.

Средство разработчика `scripts/fetch-test-models.ps1` явно скачивает небольшую
Qwen2.5-0.5B-Instruct и nomic-embed-text из официальных репозиториев. Они хранятся
в target/test-models и не входят в исходники. Маленькая модель нужна для проверки
работы движка; сложный план может не пройти проверки её вывода.

Для расширенной проверки подготовлена Qwen2.5-7B-Instruct Q4_K_M из официального
репозитория. Модель-кандидат и nomic загружаются отдельно; команды и проверенные
хеши описаны в README и scripts/privacy-models.json. На Windows каждый вызов
заново загружает GGUF, поэтому 7B на CPU ощутимо медленнее маленькой тестовой модели.
Автоматической замены настроенной вами модели нет.

Отчёт `target/privacy-eval/report.html` сравнивает модели на вымышленных данных:
попадание заданных идентификаторов в исходящий текст, принудительный L0,
блокировки, сохранение задачи и возможность связать косвенные признаки с одним
из восьми профилей. Запросы перехватываются локально после штатных проверок;
реальному провайдеру они не отправляются. Времени и модели для оценки финальных
ответов L0 этот тест не выделяет. Счётчики относятся к этому корпусу и не дают
личного «процента неузнаваемости».

Даже хорошо очищенный текст может сохранить редкое сочетание фактов или стиль.
У сервиса также могут быть ваш аккаунт, API-ключ, сведения об оплате и старые
сообщения. Текущий Tor-маршрут с ключом имеет L3; защита текста не убирает эти
привязки. Для чувствительных вопросов используйте L0 и просматривайте каждый
подготовленный удалённый запрос. Независимая проверка на новых данных остаётся
необходимой.

Песочница — отдельная обязательная граница для защищённого развёртывания.
Наличие приватного IPC само по себе не ограничивает сетевые права процесса.
`nymwrap run` запускает поддерживаемую Linux-песочницу и завершается ошибкой на
неподдерживаемой платформе вместо запуска без изоляции.

На Linux сначала запустите `nw-api`, затем из каталога проекта выполните
`nymwrap run -- /usr/bin/PROGRAM ...`. Агент видит проект на запись и единственный
HTTP socket `/run/nymwrap/api.sock`; его путь также задан в `NYMWRAP_API_SOCKET`.
Для OpenAI SDK явно настройте Unix transport, например
`httpx.HTTPTransport(uds=os.environ["NYMWRAP_API_SOCKET"])`, переданный как
`http_client=httpx.Client(transport=transport)`; `OPENAI_BASE_URL` задан внутри
песочницы. Обычный TCP transport SDK не подключится. Базы NymWrap и домашний
каталог агенту не доступны. MicroVM и прозрачный TCP-адаптер ещё не реализованы.

## Shield

Добавьте личные секреты по одному на строку и нажмите «Сохранить секреты».
Список шифруется в vault. Изменение списка начинает новые разговоры с новой
политикой. Email, телефоны, IPv4 и IPv6 ищутся автоматически. Перед удалённым
запросом локальная модель дополнительно ищет буквальные персональные сущности;
её результат проверяется кодом. Это не гарантирует обнаружения всех личных деталей.

В секреты можно добавить и известные редкие факты о себе — полными фразами и с
вариантами написания. Автоматическая NER не определяет все такие признаки;
обычная маска не понимает произвольные перефразирования. Если эти детали нужны
для решения вопроса, выбирайте локальный разговор.

«Предпросмотр» заменяет секреты, нормализует пробелы и запускает leakcheck без
модели. Это проверка детерминированных этапов, а не переписывание стиля.

«Спросить локально» использует приватный канал модели: minimize → canonicalize
→ leakcheck → локальный ответ → восстановление плейсхолдеров. Ошибка модели или
проверки останавливает операцию. Диалог ограничен числом ходов профиля.
Зашифрованная история хранится по умолчанию 30 дней. Кнопка «Новый разговор»
начинает отдельный контекст.

В standard кнопка «Спросить через Tor · L3» готовит запрос локально и показывает
каноническую историю, провайдера, модель и резерв расходов.
Окно напоминает о связывании по редким фактам, аккаунту и API-ключу и предлагает
выбрать локальный разговор для личного контекста. Отдельно одобрите
отправку или отмените её. Одобрение одноразовое, действует пять минут и не
переживает смену настроек или блокировку. Между просмотром и отправкой модель
повторно не вызывается. Чувствительный запрос получает локальный ответ L0.
Strict/paranoid запрещают имеющийся маршрут L3.

После одобрения интерфейс сохраняет задание и показывает его состояние.
В списке заданий можно посмотреть ответ, остановить ожидание или вернуть
исходный запрос в новый разговор. После прерывания отправки результат может
остаться неопределённым: провайдер мог получить запрос. Перезапуск не повторяет
его; для новой попытки снова просмотрите и одобрите текст. Отмена не отзывает
уже отправленные байты и не возвращает зарезервированный бюджет.

Один ключ закрепляется за одним разговором и не переиспользуется для другого.
Сетевые попытки учитываются до отправки; неопределённый результат тоже расходует
локальный дневной лимит. Указанная цена — ваша верхняя оценка, она не заменяет
лимит в кабинете провайдера. Ошибка Tor/HTTPS не вызывает прямую или автоматическую
повторную отправку. После смены провайдера заблокируйте пространство и откройте
его снова, затем начните новый разговор.

Фоновые приманки включаются отдельным согласием в настройках и только для
standard/Tor L3. В режиме Poisson реальные задания отправляются после одобрения,
а приманки добавляются по случайному расписанию. В режиме Constant реальные
задания ждут следующего слота; при пустой очереди слот получает приманка.
Их темы независимы от ваших данных,
каждая использует отдельный ключ; оставьте запас для своих вопросов. Слоты и
состояния попыток сохраняются зашифрованными, пропущенные слоты не догоняются,
прерванные попытки не повторяются. При исчерпанном бюджете очередь ждёт, при
блокировке работа прекращается. Подготовка модели, транспорт и задержки
провайдера могут сдвигать фактическую отправку относительно слота. Constant не
доказывает защиту от сговора провайдера с Tor guard и не включает paranoid.

## Жёсткие данные устройства

Кроме того, что вы пишете, вас выдают признаки устройства: IP, Wi-Fi и MAC,
местоположение, часовой пояс, имя компьютера и пользователя, пути к файлам.
Что делает NymWrap (подробно — SPEC §4.9):

- **IP, DNS, страна** — удалённые запросы идут только через Tor; IP компьютера
  провайдер ИИ не видит. Страна выхода не закрепляется.
- **Сведения о программе** — запрос собирается заново: без User-Agent, языка
  системы, даты и служебных заголовков SDK. Отпечаток соединения одинаков у всех
  пользователей NymWrap.
- **Секреты устройства** — при создании пространства NymWrap без сети собирает
  имя пользователя и компьютера, домашние пути, MAC-адреса, сохранённые сети Wi-Fi,
  часовой пояс, git-почту и идентификатор машины. Они хранятся в vault как
  секреты и никогда не уходят наружу. Список можно посмотреть и изменить.
- **Координаты, часовой пояс, точное время, IMEI, GUID** в тексте заменяются и
  возвращаются в ответе локально.
- **Агенты** в песочнице видят компьютер `localhost`, пользователя `user`, папку
  `/work`, часовой пояс UTC и английскую локаль.
- **Ритм** — режим Constant, отложенная отправка и приманки после закрытия
  скрывают, в какое время вы активны. При ключе провайдера (L3) все ваши запросы
  под этим ключом связаны, и их суточный ритм провайдеру виден.
- **Вложения** (фото, документы) пока не принимаются: в них бывают GPS и
  данные камеры.

Что нужно сделать вам, на экране «Гигиена»: включить случайные MAC-адреса для
Wi-Fi, убрать своё имя из имени компьютера, выключить геолокацию для
приложений и проверить синхронизацию часов. Если сеть школы или кафе не должна
видеть, что вы пользуетесь Tor, включите мост (obfs4, snowflake или webtunnel).

В полосе легенды IP и местоположение не подделываются: аккаунт и так вас знает,
а подмена сделала бы его подозрительным. Зато легенда постепенно сдвигает часы
вашей активности.

Часть этого ещё в работе — смотрите строку «Жёсткие данные» в
`docs/IMPLEMENTATION.md`.

## Приватный HTTP API для агентов

`nw-api` слушает только приватный Unix socket / Windows named pipe, указанный
командой `nymwrap paths`. Сначала откройте пространство и запустите модели.
В запросах укажите `Host: localhost`; Origin запрещён. Обычный OpenAI endpoint
`POST /v1/chat/completions` принимает `nw/local/default` или `nw/remote/default`.
Заголовок `X-NymWrap-Min-Trust` задаёт L0–L3 и может только усилить политику.

При Constant удалённому клиенту нужен асинхронный endpoint:

1. `POST /v1/nymwrap/chat/jobs` с обычным JSON chat completions и моделью
   `nw/remote/default` возвращает 202, `id` и относительный `poll_url`.
2. `GET /v1/nymwrap/jobs/{id}` возвращает состояние. В Done поле `result`
   содержит OpenAI-совместимый ответ. Опрос не отправляет запрос повторно.
3. `DELETE /v1/nymwrap/jobs/{id}` отменяет ожидание; затем проверьте состояние.

Асинхронная отправка доступна только при отключённом обязательном просмотре.
Иначе API отвечает `approval_required`, и запрос надо одобрить в интерфейсе.
Чувствительный запрос при разрешённой подготовке сразу возвращает 200 с ответом
L0. Синхронный remote endpoint при Constant возвращает `async_remote_required`.
Для защиты от повторной отправки заранее создайте случайный `Idempotency-Key`
(например UUID, 16–128 букв/цифр/`-_.`) и передайте при создании задания. Сохраните
ключ вместе с исходным JSON, conversation и min-trust. Повтор с тем же ключом и
вводом возвращает то же задание в его текущем состоянии или прежний ответ L0,
в том числе после перезапуска. Изменённый ввод — `409 idempotency_conflict`.
`409 idempotency_uncertain` означает, что попытка ещё обрабатывается или её
результат неизвестен: новый ключ может привести к повторной отправке. Проверьте
задания в приложении. При удалённой истории — `410 idempotency_expired` без
повторного исполнения. Квитанции хранятся до удаления Vault; после 8192 ключей
новые получают `429 idempotency_capacity`. Ошибка с прежним ключом также
сохраняется; для намеренно новой операции нужен новый ключ.

Без ключа не повторяйте POST после потери соединения автоматически. Сохраните
полученный id и опрашивайте его. Заголовок поддержан только асинхронным submit;
синхронные chat/embeddings с ним отклоняются. Все ответы имеют
`Cache-Control: no-store`.

## Исследование и Drift

1. Импортируйте официальный JSON/ZIP/HTML Takeout, экспорт ChatGPT, Claude,
   Gemini или браузера. Поддержаны также согласованные SQLite-истории
   Chrome/Firefox/Safari; файл с неперенесённым WAL требует SQLite backup.
   Лимит — 8 МиБ; исходный файл не изменяется. Синтетический пример доступен
   отдельной кнопкой.
2. Запустите исследование локальной моделью. Проверьте каждую предложенную черту
   по приведённым фрагментам. Отметьте соответствующие вам черты и подтвердите.
3. В Drift выберите легенду. Можно явно ввести подтверждённые интересы вручную.
4. Постройте план. Схема, безопасность тем, сервисы и геометрия этапов проверяются
   кодом; неудачная проверка блокирует план.
5. Прочитайте каждый этап и одобрите именно показанный план. Одобрение связано
   с хешем действий, сервисов и длительности этапов.
6. Подготовьте формулировки дня и одобрите их отдельно. Проверяются совпадение
   сервисов, близость к исходным действиям и позиция на оси. Одобренные действия
   текущего дня не заменяются незаметно.
7. Выполните действия в своём браузере и отметьте их. Между началами дней —
   минимум 12 часов. Перезапуск и перевод часов назад не снимают ограничение.
8. Перед следующим этапом сохраните свежий снимок Mirror. Если наблюдение
   отстаёт, переход задерживается.

Пауза останавливает выдачу и подтверждение действий. Расширение не должно видеть
Shield, vault или реальные интересы. Автоматизация веб-чатов ИИ выключена по
умолчанию. CAPTCHA и вход выполняет человек.

В настройках «Исполнение легенды» можно выбрать поиск Google/YouTube через
расширение и сохранить настройки. В popup после подключения ядра у подходящего
действия появится «Набрать запрос и открыть результаты». Эта кнопка запрашивает
разрешение на сайт и запускает одно действие в отдельной видимой вкладке:
60–180 мс на символ и 20–90 секунд на результатах. Поддержаны запросы до 512
символов. Веб-чаты ИИ и просмотр видео выполняются вручную.

Не меняйте поле или вкладку во время исполнения. «Остановить исполнение»,
закрытие вкладки, пауза, CAPTCHA/вход или потеря ядра прекращают действие.
Проверьте итог кнопкой «Состояние исполнения». Прерванная попытка автоматически
не повторяется, даже после перезапуска: запрос уже мог уйти. Проверьте вкладку
и при необходимости отметьте действие вручную. После возможной отправки Drift
переходит на паузу; продолжение требует вашей кнопки. Следующее автоматическое
действие может ждать до 15 минут, если предыдущее не отмечено.

На Windows импорт выполняется в отдельном LPAC без сетевых capabilities и
записи в каталог профиля; на Linux — через bwrap/seccomp. Эти ограничения
используются и командой `nymwrap audit`. Отказ песочницы прекращает импорт.
На macOS импорт ждёт реализации App Sandbox и сейчас недоступен.

## Подключение расширения на Windows

Соберите `extension` командой `npm ci`, затем `npm run build`. Для Chrome/Edge
загрузите распакованный каталог `extension/dist` на странице расширений
браузера и скопируйте показанный ID. В PowerShell из корня проекта выполните:

```powershell
./scripts/register-native-host.ps1 -Browser Chrome -ExtensionId ID_ИЗ_БРАУЗЕРА -BinaryPath C:\Projects\NymWrap\target\debug\nw-drift-host.exe
```

Для Edge замените Browser на Edge. Для Firefox временно загрузите manifest из
`extension/dist-firefox` и используйте `-Browser Firefox` без ExtensionId.
Регистрация меняет только HKCU и manifest NymWrap текущего пользователя. Для
удаления регистрации укажите тот же Browser и `-Unregister`. Держите пространство
открытым: native host получает только одобренные задания легенды и снимки Mirror.
После CAPTCHA или запроса входа продолжайте вручную. Установка расширения и
изменения в реальных аккаунтах автоматически не выполняются.

Если чтение карточек остановилось на CAPTCHA или входе, появится кнопка
«Приостановить Drift и учесть остановку». После подключения ядра она ставит
Drift на паузу и передаёт только случайный идентификатор и тип остановки.
Адрес и текст страницы остаются в браузере. После самостоятельного прохождения
проверки продолжите Drift отдельной кнопкой. Повтор того же сообщения в числе
последних 64 остановок не увеличивает счётчик.

«Включить ежедневные снимки» запрашивает отдельное разрешение браузера только
на YouTube. Раз в час расширение проверяет, открыта ли обычная главная YouTube
и доступно ли неприостановленное ядро. Вкладки оно не открывает. Не чаще раза
в сутки первые 30 заголовков передаются в зашифрованный Mirror; для вычисления
позиции нужны рабочая локальная модель и план. Названия и адреса страниц не
сохраняются в хранилище расширения. Там остаются настройка, времена и код состояния.

CAPTCHA, вход или отзыв разрешения выключают расписание. После проверки включите
его заново своей кнопкой. Потерянный ответ ядра или ошибка чтения не вызывают
повтор в те же сутки; при необходимости сохраните снимок вручную. Пропущенные
дни не догоняются. Рекламные темы, подсказки и память ИИ пока сохраняются вручную.

## Mirror и Purge

В Mirror вставьте до 30 заголовков ленты, рекламных тем, подсказок либо ответ ИИ
на вопрос «Что ты обо мне знаешь?». Эмбеддинги вычисляются локально; снимок и его
позиция сохраняются зашифрованными. Нулевая позиция близка к исходной персоне,
единица — к легенде. Значения могут выходить за эти границы.

График показывает отдельные линии источников; фильтр оставляет выбранный тип
снимка. Точка показывает дату и измеренную позицию при наведении или выборе
клавишей Tab. Линии соединяют наблюдения и не означают ежедневных измерений.
Точные значения остаются в таблице под графиком.

Доля в тени вычисляется по локальным запросам и реальной активности в аккаунтах,
которую вы отмечаете сами. Неучтённые действия делают оценку неполной. Прочерк
означает отсутствие данных, а не ноль.

«Приманки / удалённые запросы» учитывает только подтверждённые ответы транспорта;
L0 и запросы с неизвестным результатом в дробь не входят. «Остановки CAPTCHA /
вход» — доля учтённых остановок среди остановок и выполненных действий легенды.
Оба показателя используют события с момента поддержки этих счётчиков либо
последней очистки метрик. Старые значения не считаются измеренными нулями.
Кнопка обновления получает свежие показатели и состояние паузы из ядра.

Purge ранжирует до 300 элементов импортированной выборки по близости к исходной
персоне и частоте. Выберите записи, сервис и просмотрите партию. После одобрения
она сохраняется с хешем. Удаляйте записи вручную в указанном сервисе. Память ИИ,
история чатов и разрешение обучения — разные настройки. Шаблон запроса на удаление
генерируется без сети и отправляется вами.

В «Инструкциях по сервисам» выберите Google, YouTube, ChatGPT, Claude или Gemini.
Шаги и ссылки на официальную справку доступны локально; адрес можно скопировать
в свой браузер. Учитывайте дату проверки: интерфейсы сервисов меняются.

Ниже показаны 100 последних одобренных партий. Откройте нужную по сервису,
числу записей и хешу, отметьте выполненные шаги и сохраните наблюдаемый результат.
Для «записи больше не видны» сначала отметьте удаление выбранной истории и
повторную проверку. Это ваша отметка о видимом результате, а не доказательство
уничтожения всех копий у сервиса. Она сохраняется зашифрованной после перезапуска
и удаляется при очистке Imports. Позже её можно обновить после новой проверки.

## Уничтожение данных

В настройках выберите домен и введите «СТЕРЕТЬ». Его ключ заменяется, корневая
обёртка и секрет ОС обновляются, старые базы удаляются. Шифротекст старого домена
больше не открывается текущим набором ключей.

Для всех данных выберите соответствующий пункт и введите «СТЕРЕТЬ ВСЁ».
Удаляется секрет ОС, необходимый для доступа ко всему пространству. Восстановить
эти данные через приложение нельзя. Копии, сделанные до уничтожения вместе с
экспортированными ключами или снимками работающей ОС, находятся вне этой гарантии.
