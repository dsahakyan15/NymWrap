# NymWrap — модель угроз и требования безопасности

Читать перед любым изменением, которое касается сети, хранения, IPC, песочниц,
импорта данных или кода, обрабатывающего недоверенный текст. Архитектура — в
[`SPEC.md`](SPEC.md).

Граница задачи: максимальная защита **на уровне софта**. Аппаратные меры
(отдельный компьютер, TPM-аттестация, аппаратные ключи) — вне рамок; где они
сильно помогли бы, это отмечено как «за пределами софта».

---

## 1. Что защищаем

| Актив | Почему ценен | Где живёт |
|---|---|---|
| Реальные промпты и поиски (теневая полоса) | прямое описание человека | память core, зашифрованная локальная история |
| Vault (плейсхолдер ↔ значение) и личный список секретов | ключ к деанонимизации всех запросов | `nw-vault`, отдельный ключ |
| Персона (`persona`) | самый чувствительный файл: готовый психологический портрет | зашифрованный store, отдельный ключ |
| Импортированная история (Takeout, браузеры, экспорты ИИ) | всё прошлое человека | расшифровывается только на время импорта |
| Журнал легенды | показывает, какие действия фальшивые | отдельный ключ |
| Секреты устройства (имя ПК, SSID, MAC, machine-id, пути) | связывают анонимный запрос с конкретной машиной | `nw-vault`, вид `Device` |
| Удостоверения (zkAPI-ноты, API-ключи) | деньги и связываемость | хранилище ключей ОС |
| Связь «полоса легенды ↔ теневая полоса» | если её узнать, легенда теряет смысл | нигде не должна существовать вне core |

## 2. Противники

| # | Противник | Возможности | Чего хочет |
|---|---|---|---|
| A1 | **ИИ-провайдер** | видит содержание запросов, время, IP выхода, удостоверение, может хранить всё вечно | связать запросы с человеком и между собой |
| A2 | **Платформа профилирования** (поисковик, видео, реклама) | видит действия аккаунта, отпечаток браузера, все устройства аккаунта | точный профиль; отличить шум от сигнала |
| A3 | **Пассивный сетевой наблюдатель** (провайдер интернета, Wi-Fi) | видит метаданные трафика | понять, к каким сервисам и когда обращается человек |
| A4 | **Активный противник: провайдер + guard-узел Tor** | сговор, манипуляция временем ответов | корреляция по времени (оговорка из поста Виталика) |
| A5 | **Вредоносный контент** | веб-страницы, ответы моделей, файлы экспорта с инъекциями | заставить локальную модель или агента выдать данные или выполнить действие |
| A6 | **Локальное ПО и другие пользователи машины** | другие процессы, вкладки браузера, сайты, стучащиеся на localhost | прочитать данные NymWrap или управлять им |
| A7 | **Цепочка поставок** | подменённая зависимость, модель, обновление | код внутри доверенной границы |
| A8 | **Кража или изъятие устройства** (выключенного) | доступ к диску | прочитать всё сохранённое |
| A9 | **Оператор локальной сети** (домашний роутер, Wi-Fi школы или кафе) | видит MAC, имя компьютера в DHCP, широковещательные mDNS/LLMNR/NetBIOS, адреса назначения, факт использования Tor | узнать устройство и человека, связать его с сеансами |

Вне рамок софта: вредоносное ПО с правами администратора на работающей машине,
аппаратные закладки, изъятие включённого разблокированного устройства, принуждение
пользователя. Для них нужны аппаратные меры и отдельное устройство.

## 4. Хранение

- Отдельный ключ данных на каждый домен: `shadow_history`, `vault`, `persona`,
  `cover_log`, `imports`, `metrics`. Ключи данных обёрнуты мастер-ключом.
- Мастер-ключ = KDF(Argon2id(пароль пользователя), секрет из хранилища ОС:
  DPAPI / Keychain / Secret Service). В `standard` пароль необязателен; в `strict`
  и `paranoid` обязателен.
- База — SQLCipher; отдельные файлы — XChaCha20-Poly1305 с AAD = домен + версия.
- **Crypto-shredding**: удаление домена = уничтожение его ключа. Кнопка «стереть
  всё» уничтожает мастер-ключ.
- Временных файлов в открытом виде нет. Копии баз истории браузера при импорте
  расшифровываются только в памяти или в tmpfs с правами 0700 и удаляются сразу
  (как `sqlite_snapshot` в уроке, но с гарантией удаления при панике).
- Vault разговора живёт столько же, сколько локальная история разговора; срок
  хранения настраивается, по умолчанию 30 дней.

## 5. Журналы

- В журналы не пишется содержание: ни промпты, ни ответы, ни заголовки страниц,
  ни значения из vault. Только тип события, время (округлённое до минуты),
  длительность, код ошибки.
- В `paranoid` — только агрегированные счётчики.
- Отладочный режим с содержанием существует только в debug-сборке.

## 6. Недоверенный текст

Недоверенным считается: ответы ИИ-провайдеров, заголовки и содержимое страниц,
всё из импортированных файлов, ответы ИИ в снимках Mirror.

- Он передаётся модели внутри явно размеченного блока данных с инструкцией
  игнорировать команды внутри (приём из `persona.py` урока).
- Локальная модель, которая видит недоверенный текст, не имеет инструментов и
  доступа к vault; её вывод проходит через детерминированный код.
- Ответы провайдера не вызывают инструменты агента автоматически: агент в
  песочнице сам решает, а песочница ограничивает последствия.
- В UI всё экранируется.

## 7. Песочницы

Таблица задаёт целевую архитектуру. Наличие механизма в ОС не означает, что
все production-процессы уже запускаются в нём; текущие границы перечислены ниже.

| Процесс | Linux | Windows | macOS |
|---|---|---|---|
| все, кроме `nw-netd` | bwrap `--unshare-net --unshare-pid --die-with-parent`, seccomp-фильтр, ФС только нужные пути | AppContainer без capability `internetClient` | App Sandbox без network entitlement |
| `nw-netd` | свой netns с маршрутом только для транспорта, без доступа к домашней папке | AppContainer с сетью, без доступа к профилю пользователя | sandbox с сетью, без файлов |
| агенты (`nymwrap run`) | MicroVM (Firecracker/cloud-hypervisor) или bwrap; единственный канал — сокет `nw-api` | WSL2 с той же схемой, что Linux | sandbox-exec профиль |

Linux — эталонная платформа для `paranoid`. На Windows лучший вариант — запуск
демонов внутри WSL2 с linux-песочницами; нативный режим Windows поддерживается
в `standard` и `strict`.

Опциональная агентская MicroVM (ADR 0105/0106) подключена отдельным Linux x86_64
backend: `run --microvm /absolute/tools -- /guest/program`. Bwrap остаётся
по умолчанию. Проверяются pinned SHA-256 VMM, ядра, BusyBox/musl и guest init;
KVM/VMM недоступен или проверка не прошла — отказ без fallback. Гость без NIC,
дисков, MMDS и host mounts. Единственный прикладной канал — guest Unix socket
к фиксированному приватному shadow nw-api через virtio-vsock/host relay;
ни core RPC, ни vault, ни cover-полоса гостю не передаются. stdout/stderr и
код завершения идут по отдельным локальным vsock-каналам без записи логов.

PID 1 нормализует `localhost`, user 1000:1000, UTC/C.UTF-8, `/home/user`,
`/work`, machine-id и git identity; `/sys` и host services отсутствуют.
Непривилегированный агент получает NNP. Проект копируется в RAM с ограничением
64 MiB/4096 записей, без symlink/hardlink/special files и без writeback.
Host paths/argv/config не попадают в гостевой command line или persistent
файлы: используются sealed memfd и Zeroizing. Требуется выключенный swap на
весь срок сессии, core dumps запрещены; hibernate администратором вне защиты.
Piped `kernel.core_pattern` отклоняется, поскольку для такого crash helper
ядро игнорирует RLIMIT_CORE; это условие тоже должно сохраняться всю сессию.
Drop/PDEATHSIG завершают VMM, есть предел старта/сессии. Текущий guest runtime
минимален (BusyBox и статические программы), stdin не подключён.

У MicroVM отдельное ядро, но Firecracker/KVM и ядро хоста остаются доверенными.
VMM работает от пользователя без root, наследует запрет IP-сокетов и NNP;
jailer/полная файловая песочница самого VMM ещё не подключены. Поэтому VM escape
в VMM не покрыт дополнительной файловой границей, а наличие этого backend не
закрывает весь M6. Реальная проверка KVM, TCP/UDP/DNS denial и сокетного запроса
обязательна в CI `linux-microvm`; локальный Windows-тест её не заменяет.

Текущее сетевое разделение (ADR 0082): административный Linux launcher до Tokio
создаёт пустой netns core, запускает retained netd в заранее подготовленном
отдельном netns, сбрасывает UID/GID/groups и запрещает IP-сокеты core через
seccomp TSYNC. Ограничение маршрутов/firewall netd обязан подготовить доверенный
coordinator. Без него Linux desktop доступен только в L0. Полная файловая
песочница демонов ещё относится к M6.

Windows LPAC изолирует workers и API; отдельный неограниченный модельный брокер
заменён Rust-шаблоном в core, каждый вызов модели получает свежий LPAC. Cover native host
обрабатывает команды в отдельном LPAC-процессе. Linux API/модель/cover host
получают bwrap и seccomp из профилей nw-sandbox (ADR 0092); выданы только
собственный каталог listener, нужные сокеты и read-only модели. Отдельные
отрицательные тесты проверяют сеть, чужие файлы, дочерние процессы и IPC полос.
Минимальный stdio-переходник браузера пока остаётся снаружи. Windows core/netd не помещены в
AppContainer. На macOS есть явный `nw-sandbox` launcher с deny-default Seatbelt
профилями для каждой роли (ADR 0094): IP только netd, приватный каталог одной
полосы, точные read-only файлы модели/импорта и клиентские Unix-сокеты, без
location/Wi-Fi/Mach/IOKit прав. Используется устаревший `sandbox-exec`, не
Apple Developer App Sandbox; отказ прекращает запуск. Автоматическая production
интеграция desktop/core со всеми children пока не подключена. Поэтому
на этих ОС прикладной Tor fail-closed не заменяет запрет сокетов для остальных
процессов и не даёт Linux namespace-гарантию; оба пункта M6 остаются открытыми.

Отдельный доверенный `nw-probe` на macOS до приёма входных данных применяет
deny-default Seatbelt-профиль и проверяет запрет TCP/UDP. Разрешены только чтение
системных источников и переданный read-only git-файл; запись, дочерние процессы
и внешняя сеть запрещены. Ошибка политики завершает worker. Это не App Sandbox
для остальных демонов. Нативный macOS CI подтвердил Seatbelt и точные
отказы TCP/UDP `bind`/`connect`; недоступность sandbox не пропускается.

Полнота probe требует явного подтверждения каждого из девяти источников.
Пропущенный источник, старый снимок без такого подтверждения и частичное чтение
не разрешают выход при включённой защите устройства. Недоступные Windows API и
неполный каталог Wi-Fi macOS остаются неизвестными, без новых Wi-Fi/location
capabilities. Наблюдения гигиены не считаются доказательством отсутствия пакетов.

Управляемый PT теперь обязан применить файловую песочницу (ADR 0085): Linux
bwrap отделяет mount/PID/user/IPC/UTS, оставляя только транспортный netns netd;
доступа к core IPC, vault и состоянию остальных разговоров нет. macOS использует
обязательный sandbox-exec, Windows отклоняет запуск до реализации изоляции PT.
Нет повторного запуска без песочницы. Drop управляемого ребёнка и Linux
die-with-parent ограничивают lifetime; общая crash-lifetime демонов остаётся M6.
Локальный obfs4 pcap и реальные PT namespaces подтверждены зелёным CI run
45780888200: все признаки UID/capabilities/NNP/storage/IPC/stop-with-live-Tor обязательны.

## 8. Остаточные риски (честно показываются пользователю)

- Сговор ИИ-провайдера с guard-узлом Tor позволяет корреляцию по времени; mixnet
  снижает, но не исключает.
- Содержание переписанного запроса провайдер видит всегда (кроме L0). Уникальная
  задача может выдать человека и без PII.
- Аккаунт легенды связан с человеком по телефону, оплате и устройствам; меняется
  представление о человеке, а не его личность.
- Данные, уже ушедшие в обучение моделей и к брокерам данных, программа не удаляет,
  а только уменьшает их влияние и подаёт запросы на удаление.
- Пока пользователь продолжает реальную активность в аккаунте, дрейф медленный
  (метрика `shadow_share`).
- Локальная модель тоже может ошибиться в classify; поэтому личный список секретов
  и leakcheck детерминированы.
- Guard-узел Tor (или мост) видит настоящий IP; провайдер интернета видит, когда
  компьютер включён. Скрыть время работы машины от собственного провайдера
  интернета софт не может.
- Отпечаток TLS/HTTP отличает пользователей NymWrap от обычных клиентов; внутри
  этой группы установки неотличимы.
- Ядро ОС, модель процессора и реальное время часов видны агенту в песочнице;
  это низкоэнтропийные признаки, но не ноль.
- MAC-рандомизация и имя компьютера — настройки ОС; NymWrap только проверяет их.
- Детекторы ловят форматы, а не смысл: «живу у второго выхода метро на площади
  Республики» — геоданные без координат. Это закрывают личные секреты и L0.

## 9. Чек-лист укрепления (критерий закрытия M6)

Сверка на 2026-11-26 для `7bc1ca3`: M6 **не закрыт**. Галочки ниже означают
зелёный CI для указанного теста и области, не готовность всей системы.
Полная таблица доказательств и причин открытых пунктов —
[IMPLEMENTATION: итоговая сверка](IMPLEMENTATION.md#итоговая-сверка--2026-11-26).

- [ ] Каждый процесс запускается только через `nw-sandbox` с профилем из репозитория.
  Частично: [core Windows][tm-core-windows]/[Linux][tm-core-linux] проверяют
  отдельные workers, [Seatbelt][tm-seatbelt] — launcher. Полная изоляция core,
  брокер ключей/запуска, общие
  netd/stdio-профили и подключение launcher к macOS desktop не завершены
  ([ADR 0092](adr/0092-leaf-daemon-sandbox-profiles.md),
  [0093](adr/0093-core-key-and-launch-broker.md),
  [0094](adr/0094-macos-seatbelt-process-profiles.md)).
  [MicroVM CI][tm-microvm] зелёный, но backend opt-in и без jailer
  ([ADR 0105](adr/0105-opt-in-shadow-agent-microvm.md),
  [0106](adr/0106-pinned-microvm-tools.md)).
- [ ] Тест: процессы, кроме `nw-netd`, не могут открыть внешний сокет.
  Частично: [tor-pcap][tm-pcap] подтверждает Linux core netns,
  [core Windows][tm-core-windows]/[Linux][tm-core-linux] — API/модель/cover host,
  [Seatbelt][tm-seatbelt] — роли launcher с отрицательным TCP/UDP IPv4/IPv6
  контролем и положительной доставкой только у netd. Windows core не изолирован,
  брокер ADR 0093 не реализован; macOS desktop не использует launcher автоматически
  (ADR 0094). Проверка workers не закрывает весь пункт.
- [x] Тест: остановка транспорта → ни одного байта мимо него.
  [tor-pcap (tor)][tm-pcap] и [tor-pcap (obfs4)][tm-pcap-obfs4]: явный отказ при
  остановке, провайдер остаётся жив, ноль direct-provider/DNS packets. Область —
  Linux production launcher и локальная синтетическая Tor-сеть.
- [x] Тест: канарейки не появляются в захвате трафика ни в одном из 6 кодирований.
  [core Linux][tm-core-linux]: 100 канареек/6 форм после модели;
  [network Linux][tm-network-linux]: `every_pcap_canary_and_encoding_is_vetoed_after_a_model_reintroduction`;
  [tor-pcap][tm-pcap]: независимая проверка захвата ОС. Это не доказательство
  смысловой несвязываемости; отрицательная оценка linkcheck остаётся открытой.
- [x] Тест: файлы данных не содержат открытого текста тестовых промптов.
  [core Linux][tm-core-linux]: `domain_files_never_contain_plaintext` и
  `persists_reopens_expires_and_shreds_without_plaintext`, синтетические данные.
- [ ] Core dump запрещены, ключи в `mlock`, проверено тестом.
  Частично: [core Linux][tm-core-linux]/[Windows][tm-core-windows]/[macOS][tm-core-macos]
  проверяют `keys_are_locked_and_independent_drops_retain_other_locks`.
  Запрет дампов реализован в `harden_process`, но отдельного CI-теста запрета
  дампа всех production-процессов/его содержимого нет.
  [ADR 0003](adr/0003-os-security-boundary.md).
- [x] IPC отвергает сообщение с чужой полосой.
  [core Linux][tm-core-linux]: `private_roundtrip_rejects_foreign_lane_and_oversize`,
  `rejects_forged_lane_version_unknown_fields_and_oversize`, процессный RPC suite.
- [ ] `cargo-deny` и `cargo-vet` зелёные, SBOM приложен к релизу.
  Частично: [cargo-deny][tm-deny], [source SBOM][tm-sbom] и [vet fuzz][tm-vet-fuzz]
  зелёные; [root][tm-vet-root] — 7, [netd][tm-vet-netd] — 20,
  [desktop][tm-vet-desktop] — 5 пробелов, все три jobs красные.
  Поштучные exemptions по недостижимости также запрещены gate
  [ADR 0073](adr/0073-locked-dependency-audit-gates.md); решения владельца нет.
  Native/FFI review и находки:
  [ADR 0102](adr/0102-root-dependency-audit-sources.md),
  [0103](adr/0103-netd-dependency-audit-sources.md),
  [0104](adr/0104-desktop-dependency-audit-sources.md),
  [0109](adr/0109-secret-service-openssl.md),
  [0110](adr/0110-cargo-vet-findings-and-ipc-reachability.md).
  SBOM доступен в CI/неподписанном кандидате, подписанного релиза ещё нет.
- [ ] Релиз подписан ключом выпуска (ADR 0080), сборка воспроизводима на двух машинах.
  Частично: [clean-linux-a][tm-repro-a], [clean-linux-b][tm-repro-b] и
  [compare][tm-repro-compare] зелёные на том же SHA, `identical=true`.
  Только Linux x86_64; первый выпуск не подписан. Локальная пересборка,
  сравнение и подпись владельцем остаются по
  [ADR 0080](adr/0080-release-signing-with-tauri-signer.md),
  [0098](adr/0098-reproducible-linux-release.md),
  [0099](adr/0099-owner-signed-release-handoff.md).
- [ ] Фаззинг импортеров и IPC — 24 часа без падений.
  Идёт, падений пока нет по опубликованным jobs на 2026-11-26 15:43 UTC:
  [run 45813366602](https://github.com/dsahakyan15/NymWrap/actions/runs/45813366602),
  SHA `916a5e8`, `in_progress`. Текущие сегменты ещё без полных логов/итога.
  Ориентир окончания — 2026-11-27 около 13:30 UTC. Нужны все 18 receipts и
  зелёная итоговая проверка; это 6×4 ч с перезапусками на каждую цель,
  не суточная кампания финального SHA. [ADR 0096](adr/0096-task10-hosted-fuzz-campaign.md).
- [x] UI: CSP запрещает inline-скрипты и внешние источники.
  [frontends][tm-frontends]: `local UI has restrictive CSP and no network or content persistence`;
  [desktop][tm-desktop]: сборка Tauri. Не закрывает находки зависимостей ADR 0110.
- [x] Тест: синтетические секреты устройства и значения всех детекторов жёстких данных не появляются в захвате трафика.
  [tor-pcap (tor)][tm-pcap]/[obfs4][tm-pcap-obfs4]: 9 Device-источников,
  7 детекторов, `canary_leaks=0`. Неполный probe реальной машины остаётся неполным.
- [x] Golden-тест: заголовки и ClientHello одинаковы на всех ОС CI.
  [protocol-golden][tm-golden] сравнивает реальные Windows/Linux/macOS artifacts;
  TLS random/key share исключены согласно SPEC.
- [x] Тест: агент в песочнице видит только нормализованное окружение (SPEC §4.9.5).
  Linux bwrap: [core Linux][tm-core-linux], явно запущенный actual-agent test;
  opt-in Firecracker: [linux-microvm][tm-microvm], настоящий KVM guest.
  Эти проверки не относятся ко всему desktop или агентам других ОС.
- [ ] Ни один процесс NymWrap не имеет capability геолокации или Wi-Fi.
  Частично: [core Windows][tm-core-windows], [Seatbelt][tm-seatbelt],
  [core Linux][tm-core-linux] подтверждают отдельные профили/агента.
  Полный набор production-процессов не изолирован/не проверен:
  [ADR 0085](adr/0085-explicit-device-coverage-and-isolated-pt.md),

  [0094](adr/0094-macos-seatbelt-process-profiles.md).
