# NymWrap

Локальная программа, которая постепенно меняет то, что сервисы и ИИ «думают» о
человеке: реальная активность уходит в анонимную **теневую полосу** (Shield), а
аккаунты человека получают только постепенно дрейфующую **легенду** (Drift).
Purge уменьшает старые следы, Mirror измеряет результат.

## Документы

- `docs/SPEC.md` — что строим: архитектура, процессы, модули, интерфейсы, этапы M0–M7 с критериями приёмки. Читать перед любой задачей по коду.
- `docs/THREAT_MODEL.md` — противники, защиты, хранение, песочницы, чек-лист. Читать перед изменением сети, хранения, IPC, песочниц, импорта, Shield (включая жёсткие данные, SPEC §4.9) или кода, который обрабатывает недоверенный текст.
- `docs/USER_GUIDE.md` — для людей; обновлять, когда меняется поведение, видимое пользователю.
- `docs/adr/` — принятые решения. Новое решение по стеку, зависимости или инварианту оформляется как ADR.
- `web3lesson/` — урок, из которого взята математика дрейфа (`anti.py`, README раздел «The math»). Это справочник: код оттуда не импортируется.

## Инварианты

Каждое изменение сохраняет все восемь. Изменение, которое требует нарушить
инвариант, начинается с ADR и вопроса пользователю.

1. **Полосы раздельны.** У каждого процесса, сообщения и домена хранения ровно одна полоса (`shadow` или `cover`). Процессы легенды получают только текст легенды; vault, реальная история и Shield доступны только теневой полосе.
2. **Выход только через `nw-netd`.** Все остальные процессы работают без сети. Каждый удалённый запрос проходит `leakcheck` после последнего этапа с моделью. Транспорт fail-closed.
3. **Последнее слово за детерминированным кодом.** Вывод модели (переписывание, классификация, планы) проверяется кодом до того, как что-то покинет машину или будет исполнено.
4. **На диске только шифротекст.** Отдельный ключ на домен; открытый текст живёт только в памяти, секреты в `secrecy`/`zeroize`.
5. **Недоверенный текст — данные.** Ответы моделей, страницы и импортированные файлы передаются в кавычках, экранируются в UI и никогда не исполняются.
6. **Человек одобряет.** Планы дрейфа, партии удаления и (в `strict`/`paranoid`) каждый исходящий запрос одобряет пользователь.
7. **Честная автоматизация.** Человеческий темп, остановка на CAPTCHA и входе, без маскировки отпечатка; автоматизация веб-чатов ИИ только по явному включению.
8. **Журналы без содержания, без телеметрии.** Пишутся тип события, время, код ошибки.

## Работа с кодом

- Rust-workspace в `crates/`, расширение в `extension/` (TypeScript), UI в `app/` (Tauri). Команды сборки и тестов смотреть в `Cargo.toml`, `extension/package.json` и CI.
- Работа идёт по этапам SPEC §9; этап закрыт, когда все его критерии приёмки зелёные в CI.
- Новая зависимость: закреплённая версия, хеш в lock-файле, `cargo-deny` зелёный, причина в ADR.
- Любой код на пути к выходу получает канареечный тест в `tests/leak/`.
- Перед завершением задачи: `cargo test --workspace`, `cargo clippy -- -D warnings`, тесты утечек и тесты расширения зелёные.
- Персональные данные (свои или тестовые реальные) в репозиторий не попадают; фикстуры синтетические.
